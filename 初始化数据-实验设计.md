# EasyNCO 初始化阶段离线评测实验设计

## 1. 目标与总原则

本方案的目标是：

- 只评测 **初始化阶段**；
- 不跑迭代改进；
- 尽量覆盖 [统计.md](/mnt/d/study/3/neural-solver-selection/统计.md) 中已经统计到的所有问题与方法；
- 对于同一个问题，所有方法必须使用 **同一批固定测试实例**，不能各自随机生成；
- 尽量优先使用 `100` 规模；如果某问题或某方法没有合适的 `100` 规模，就改用该问题/该方法的常用 benchmark 规模。

统一口径：

- 训练/测试入口统一优先使用 [EasyNCO/eval.py](/mnt/d/study/3/neural-solver-selection/EasyNCO/eval.py)。
- 所有学习方法统一设置：
  - `mode=test`
  - `decoder_strategy=greedy`
  - `settings.iteration._target_=EasyNCO.neural_solvers.pipeline.NoIteration`
- `test_data_path` 一律指向固定保存的数据文件或固定数据目录。
- `episodes` 必须等于测试集真实实例数。
- 除非特别说明，以下命令都假设在 `EasyNCO/` 根目录执行。

这样做的含义是：

- 对默认带迭代的方法，例如 `LEHD / LIH / DACT / UDC / DIFUSCO / T2T / GLOP / DeepACO / L2S`，通过覆盖 `NoIteration`，只取它们的初始化结果；
- 对默认本来就只有初始化的方法，例如 `ELG / INVIT / ICAM / Pointerformer / DPN / PSL / MTPOMO / MVMoE / DRL-HGNN`，同样走统一入口，只是 `NoIteration` 不会改变行为。

## 5.5 SOP100：调用 EasyNCO 的 `SOPGenerator`

说明：

- `SOPGenerator` 的随机生成器返回的是拼接后的矩阵；
- 但自定义 loader 读取 `.pt` 时，期望的是 `(distance, adj_mat, mask)` 这种三元组；
- 所以下面仍然调用平台 generator，只是在保存前把单个样本拆回 loader 期望的格式。

```bash
mkdir -p data/datasets/offline_init_v1/sop

PYTHONPATH=.. python - <<'PY'
import torch
import numpy as np
from EasyNCO.data.SOPGenerator import SOPGenerator

torch.manual_seed(2024)
np.random.seed(2024)

problem_size = 100
loader = SOPGenerator(
    data_size=10000,
    problem_size=problem_size,
    batch_size=256,
    device='cpu',
)
samples = []
for i in range(len(loader.dataset)):
    sample = loader.dataset[i].cpu()
    distance = sample[:problem_size]
    adj_mat = sample[problem_size:]
    mask = torch.zeros(1)
    samples.append((distance, adj_mat, mask))
torch.save(samples, 'data/datasets/offline_init_v1/sop/test_sop100_random_10000.pt')
PY
```

## 5.6 SMTWTP100：调用 EasyNCO 的 `SMTWTPGenerator`

说明：

- `SMTWTPGenerator` 随机生成器返回 `(n, 3)` 张量；
- 但自定义 loader 读取 `.pt` 时，期望的是 `(dummy_graph, due_time, weights, processing_time)`；
- 所以下面同样先调用平台 generator，再转换成 loader 期望的保存格式。

## 5.12 不建议自己随机生成的 benchmark 型问题

下面这些问题更适合直接准备固定 benchmark，而不是自己随手造一批 synthetic：

- `MIS`
  - 当前平台没有稳定的 random graph generator 闭环；
  - 推荐直接准备固定目录：
    - `data/datasets/offline_init_v1/mis_er/`
    - `data/datasets/offline_init_v1/mis_sat/`
- `JSSP`
  - 推荐直接放公开 benchmark `.npy` 文件；
  - 注意文件名最好就是 `la15x15.npy`、`ft10x10.npy` 这类标准名，因为 loader 会去查 `LIBUtils.py` 里的标准结果表。
- `FJSP`
  - 推荐直接放 `public_fjsp_dataset/` 或标准 `.fjs` benchmark。
- `RCPSP`
  - 推荐直接放 `PSPLIB J120` 的 `.RCP` 目录。

## 8. 启发式初始化器的同批数据评测流程

平台内现成启发式初始化器是 [INSERTIONInitialization](/mnt/d/study/3/neural-solver-selection/EasyNCO/neural_solvers/methods/insertion/initialization.py)。

支持：

- `TSP`: `random / nearest / farthest / median / regret`
- `CVRP`: `random / nearest / farthest / median`

思路：

- 仍然走 `eval.py`
- 但把 `settings.initialization._target_` 改成 `INSERTIONInitialization`
- `iteration` 强制 `NoIteration`
- `policy` 和 checkpoint 只作为壳子存在
- `TSP` 用 `lehd_tsp100.ckpt`，`CVRP` 用 `lehd_cvrp100.ckpt` 即可

## 9. 经典 / exact solver 在同一批固定数据上的评测流程

平台内 exact solver 在 [exact_solver_main.py](/mnt/d/study/3/neural-solver-selection/EasyNCO/exact_solvers/exact_solver_main.py)，但默认 [use_main.py](/mnt/d/study/3/neural-solver-selection/EasyNCO/exact_solvers/use_main.py) 会自己随机生成数据，不符合“同一批固定数据”的要求。

因此建议你在服务器上临时写一个辅助脚本，直接从固定 `.pt` 数据集读取，再调用 `exact_solver_main`。

先创建辅助脚本：

```bash
cat > /tmp/run_exact_init_benchmark.py <<'PY'
import os
import sys
import argparse
import torch
from omegaconf import OmegaConf

sys.path.insert(0, os.path.dirname(os.getcwd()))
from EasyNCO.exact_solvers.exact_solver_main import exact_solver_main

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--solver", required=True)
    parser.add_argument("--ptype", required=True, choices=["tsp", "cvrp", "atsp"])
    parser.add_argument("--data_path", required=True)
    parser.add_argument("--problem_scale", type=int, required=True)
    parser.add_argument("--problem_number", type=int, required=True)
    parser.add_argument("--cpus", type=int, default=8)
    parser.add_argument("--capacity", type=int, default=50)
    parser.add_argument("--demand_scale", type=int, default=50)

    parser.add_argument("--int_matrix_scale", type=int, default=1000000)
    parser.add_argument("--ortools_num_vehicles", type=int, default=30)
    parser.add_argument("--pyvrp_num_vehicles", type=int, default=30)
    parser.add_argument("--gurobi_num_vehicles", type=int, default=30)
    parser.add_argument("--cplex_num_vehicles", type=int, default=30)
    args = parser.parse_args()

    cfg = OmegaConf.load("exact_solvers/configs.yaml")
    cfg.solver = args.solver
    cfg.ptype = args.ptype
    cfg.problem_scale = args.problem_scale
    cfg.problem_number = args.problem_number
    cfg.cpus = args.cpus
    cfg.solver_mode = "multi"
    cfg.capacity = args.capacity
    cfg.demand_scale = args.demand_scale
    cfg.int_coord_scale = args.int_coord_scale
    cfg.int_matrix_scale = args.int_matrix_scale
    cfg.ortools_num_vehicles = args.ortools_num_vehicles
    cfg.pyvrp_num_vehicles = args.pyvrp_num_vehicles
    cfg.gurobi_num_vehicles = args.gurobi_num_vehicles
    cfg.cplex_num_vehicles = args.cplex_num_vehicles

    obj = torch.load(args.data_path, map_location="cpu")

    if args.ptype == "tsp":
        node_xy = obj["node_xy"][:args.problem_number]
        data_list = [[(float(x), float(y)) for x, y in inst.tolist()] for inst in node_xy]
    elif args.ptype == "cvrp":
        depot_xy = obj["depot_xy"][:args.problem_number]
        node_xy = obj["node_xy"][:args.problem_number]
        node_demand = obj["node_demand"][:args.problem_number]
        data_list = []
        for depot, locs, demand in zip(depot_xy, node_xy, node_demand):
          data_list.append([
              depot.squeeze(0).tolist(),
              locs.tolist(),
              demand.tolist(),
              args.capacity,
          ])
    else:
        mats = obj[:args.problem_number]
        data_list = [m for m in mats]

    result = exact_solver_main(cfg, data_list=data_list)
    print(result)

if __name__ == "__main__":
    main()
```
