# `1two_gate/` 双 Gate 强化学习选择器（TSP 原型）实现说明

本文档整理你当前在 `1two_gate/` 目录下**已经完成**的实现与对应的设计思路，目标是把“从求解器级选择 → pipeline 组件级选择（初始化/迭代）”这条路线，用一个可运行的强化学习框架先跑通。

> 说明：这里的“求解器组件”来自你自己的平台 `EasyNCO/`。`1two_gate/` 只做 gate、特征、训练 loop 和封装调用，尽量不改 `EasyNCO/`。
> 补充：文档里的路径已统一写为当前命名；但当前代码默认输出目录字符串仍可能残留为 `my/outputs`，这是代码层的历史残留。

---

## 1. 研究动机与问题设定（来自这条线早期思路记录的实现化版本）

### 1.1 前提与原论文局限

- 前提：单一模型不可能适配所有实例，模型存在偏向性。
- 原论文（作者仓库 `neural-solver-selection/`）做法：一个 gate 在“完整求解器集合”上做选择；监督信号来自离线跑全 solver zoo 得到的标签。
- 你的观察：把一个 solver 当整体有隐含假设——“同一条 pipeline（初始化 + 迭代/改进）对所有实例都合适”。但初始化阶段与迭代阶段可能对实例有不同偏好，所以希望把 pipeline 细化并解耦选择。

### 1.2 你的新设定：双 gate 解耦 pipeline

- **Gate1（初始化选择）**：输入实例 `data`，从初始化器集合中选一个，得到初始解 `sol0`。
- **Gate2（迭代选择）**：输入 `data + sol0`，从迭代器集合中选一个，在固定迭代步数下得到最终解 `sol1`。
- 组合爆炸：初始化器×迭代器是 `n*m` 种组合，做全组合离线标注代价过高 → 采用强化学习在线试错。

### 1.3 强化学习约定（你明确的要求）

- 强化学习范式：Actor-Critic（AC）。
- 奖励：`reward = -length`（目标是最小化路径长度）。
- baseline：batch 内 `mean(length)`（实现里转到 reward 空间）。
- loss：最终 reward 同时归因到两次决策（Gate1 与 Gate2）。
- 时间先不考虑：迭代阶段固定迭代次数，只选择“迭代方式”。

## 2. 总体架构：一次训练 step 的数据流（对应 `1two_gate/train_two_gate_tsp.py`）

用一个 batch 的随机 TSP 实例（点坐标）来描述一次训练 step：

1. **采样实例**：`coords ~ Uniform([0,1]^{N×2})`
2. **Gate1**：
   - 特征：`f1 = φ1(coords)`（实例特征）
   - 策略：`a1 ~ Categorical(logits = gate1(f1))`
   - 执行：`sol0 = initializer[a1](coords)`（来自 `EasyNCO/`）
3. **Gate2**：
   - 特征：`f2 = φ2(coords, sol0)`（实例+初始解条件特征）
   - 策略：`a2 ~ Categorical(logits = gate2(f2))`
   - 执行：`sol1 = iterator[a2](coords, sol0)`（来自 `EasyNCO/`）
4. **奖励**：`length = sol1.length`，`reward = -length`
5. **baseline 与 advantage**：
   - batch mean：`baseline_reward = -mean(length)`
   - critic（可选）：`V(s)` 预测 reward 或 reward 残差
   - `adv = reward - baseline`
6. **联合策略梯度**：
   - `actor_loss = -mean((logp1 + logp2) * adv.detach())`
   - `critic_loss = MSE(目标, 预测)`
   - `loss = actor_loss + critic_coef * critic_loss`

关键点：**只有 gate（以及可选 critic）被训练**；初始化器/迭代器作为外部组件固定使用（可加载 checkpoint，但不反向传播）。

## 3. 代码组织：`1two_gate/` 各文件职责

- `1two_gate/train_two_gate_tsp.py`：训练/评估入口（TSP 原型）；组装 zoo、组装 gate、训练 loop、评估与保存 checkpoint。
- `1two_gate/features.py`：Gate1/Gate2 特征提取（状态空间）；默认用论文风格 encoder（本地实现）+ scale；Gate2 额外拼接 `sol0` 条件信息（length0 + tour 统计量）。
- `1two_gate/paper_encoder.py`：在 `1two_gate/` 内重写的“论文风格”编码器（`Naive_Encoder` / `Encoder_h`），避免直接 import 作者仓库根目录的 `model.py`。
- `1two_gate/gates.py`：gate 的 MLP 与 critic 的 value MLP；`TwoGateAC` 把这些模块组合成一个可 checkpoint 的对象。
- `1two_gate/solver_zoo.py`：对 `EasyNCO/` 的初始化/迭代组件做轻量封装，提供统一的 `Initializer/Iterator` 接口，以及按 action 分组执行的 batch wrapper。
- `1two_gate/easynco_bootstrap.py`：运行时确保本地 `EasyNCO/` 可导入，并加轻量 stub，减少不必要的重依赖导入。
- `1two_gate/checkpoints.py`：加载 `EasyNCO/` solver policy checkpoint 的兼容函数（处理常见前缀与保存格式）。
- `1two_gate/TRAINING_GUIDE.md`：运行方式与参数说明（你当前原型的“用户手册”）。

## 4. 训练入口：`1two_gate/train_two_gate_tsp.py`（做了什么，怎么做的）

### 4.1 配置：`TrainConfig` 与 CLI

`TrainConfig` 是一个 dataclass，覆盖：

- 训练超参：`seed/device/problem_size/batch_size/train_steps/lr/log_every/eval_every/eval_batches`
- zoo 配置：
  - `init_zoo=("pomo","am")`（可扩展 `"lehd"`）
  - `iter_zoo=("none","rrc_lehd")`（可选附加 `--add_two_opt`）
- solver 相关：
  - `pomo_size`（不传则默认等于 problem_size）
  - `decoder_strategy="greedy"|"sampling"`
  - `rrc_steps`（迭代固定步数）
  - 可选 solver checkpoint：`pomo_ckpt/am_ckpt/lehd_ckpt`
- 强化学习 baseline/AC：
  - `baseline="batch_mean"|"critic"|"critic_batch_mean"`
  - `critic_coef`（权衡 actor/critic）

CLI 参数在 `main()` 中映射到该 dataclass，并打印为 JSON 方便复现实验。

### 4.2 数据：在线生成随机 TSP（无限数据）

`_make_tsp_batch(batch_size, problem_size, device)` 直接生成 `[B,N,2]` 坐标：

- `coords = torch.rand((B,N,2), device=device)`

这满足“框架先跑通”的目标：不依赖数据集文件，训练样本可无限生成。

### 4.3 初始化器 zoo：`_build_initializer_zoo()`

这里“组装外部组件”，并统一封装成 `1two_gate/solver_zoo.py:NeuralARInitializer`：

- `pomo`
  - 环境：`EasyNCO.neural_solvers.envs.TSPEnv.TSPEnv(problem_size=N, pomo_size=pomo_size, ...)`
  - policy：`EasyNCO.neural_solvers.methods.pomo.policy.POMOPolicy`
  - initialization：`EasyNCO.neural_solvers.methods.pomo.initialization.POMOInitialization`
  - 特点：一次 rollout 产生 `[B,pomo,N]` 的多条解，wrapper 会为每个实例挑选 reward 最大（length 最小）的那条作为 `sol0`。
- `am`
  - 环境：同上，但 `pomo_size=1`
  - policy：`EasyNCO.neural_solvers.methods.am.policy.AttentionModelPolicy`
  - initialization：`EasyNCO.neural_solvers.pipeline.initialization.ARInitialization`
- `lehd`（可选）
  - 环境：`method_name="lehd"` 的 `TSPEnv`
  - policy：`EasyNCO.neural_solvers.methods.lehd.policy.LEHDPolicy(phase="test")`
  - initialization：`EasyNCO.neural_solvers.methods.lehd.initialization.LEHDInitialization`

对 solver policy 的处理：

- `policy.requires_grad_(False)`：明确 solver 不训练（只训练 gate）。
- 若提供 `*_ckpt`，用 `1two_gate/checkpoints.py:load_policy_checkpoint()` 加载权重，并打印 missing/unexpected keys 数量作为兼容性提示。

### 4.4 迭代器 zoo：`_build_iterator_zoo()`

迭代器封装为 `1two_gate/solver_zoo.py:Iterator`：

- `none`：`NoIterationIterator()`，直接返回 `sol0`（用于对照）。
- `rrc_lehd`：`RRCLIHStyleLEHDIterator(...)`
  - env：`TSPEnv(method_name="lehd", pomo_size=1, ...)`
  - policy：`LEHDPolicy(phase="test")`，同样可选加载 `lehd_ckpt`
  - 固定迭代次数：`max_steps = cfg.rrc_steps`（满足“先不考虑时间，固定迭代次数”的要求）
- 可选调试：`--add_two_opt`
  - 追加一个确定性局部搜索：`TwoOptIterator(max_iterations=cfg.two_opt_iters)`

### 4.5 Gate 与 critic：`_build_gates()`

这一步把“特征提取 + gate 网络 + value 网络（可选）”组装起来：

1) 特征提取配置：`FeatureConfig()`（默认 `extractor="paper"`）  
2) encoder：`build_paper_tsp_encoder(feat_cfg)`  
3) 用 dummy batch 推一次前向，自动推断维度：

- `d1 = dim(tsp_instance_features(...))`（Gate1 输入维度）
- `d2 = dim(tsp_gate2_features(...))`（Gate2 输入维度）

4) Gate1/Gate2 网络：`build_mlp(GateMLPConfig(in_dim=d*, out_dim=num_actions))`  
5) critic/value：当 `baseline in ("critic","critic_batch_mean")` 时构建 `build_value_mlp(in_dim=d1)`  
6) 组合：`policy = TwoGateAC(encoder, gate1, gate2, value)`；优化器：`Adam(policy.parameters(), lr)`

### 4.6 训练 loop：`train(cfg)`

每个 step 的关键逻辑如下（与第 2 节一致）：

- Gate1：`dist1 = Categorical(logits=gate1(feat1)); a1 = dist1.sample(); logp1 = dist1.log_prob(a1)`
- 执行初始化：`sol0 = run_initializers_by_action(coords, a1, init_zoo)`
- Gate2：同样采样 `a2, logp2`
- 执行迭代：`sol1 = run_iterators_by_action(coords, a2, sol0, iter_zoo)`
- 奖励：`reward = -sol1.length`
- baseline 三种模式（见下一节）
- `adv = reward - baseline`
- 联合 actor loss：`-((logp1+logp2) * adv.detach()).mean()`
- 加上 critic loss：`loss = actor_loss + critic_coef * critic_loss`

日志（用于验证框架是否正常工作）：

- `len0/len1`：初始化解与最终解的平均长度
- `adv` 的均值/方差
- 两个 gate 的 entropy（看探索是否塌缩）
- `gate1/gate2` 的 action 分布（看是否开始偏向某些组件）

### 4.7 评估：`evaluate(cfg, ...)`（greedy）

评估阶段用 greedy（`argmax`）而不是采样：

- `a1 = gate1(feat1).argmax(dim=1)`
- `a2 = gate2(feat2).argmax(dim=1)`

输出：

- `mean_len`：多个 eval batch 的平均路径长度
- `gate1_dist/gate2_dist`：greedy 下动作分布

### 4.8 保存与恢复

训练结束会把 checkpoint 保存到 `1two_gate/outputs/`：

- 保存内容：`cfg + encoder/gate1/gate2/value 的 state_dict + optimizer state`
- 不保存 solver：因为 solver 属于外部固定组件（来自 `EasyNCO/`），原则上不由 `1two_gate/` 管理参数

恢复训练/只评估：

- `--load` 加载 gate checkpoint（encoder/gates/value/optimizer）
- `--only_eval` 只做 greedy 评估然后退出

## 5. Baseline：batch mean 与 critic 是否冲突？当前实现如何“兼顾两者”

你在实现里支持三种 baseline 模式（`TrainConfig.baseline`），核心都在 `1two_gate/train_two_gate_tsp.py`：

### 5.1 `batch_mean`（严格按你的原始说明）

- `baseline_length = length.mean()`
- `baseline = -baseline_length`（转为 reward 空间）
- 不训练 value 网络（`policy.value=None`）

### 5.2 `critic`（标准 AC：用 V(s) 直接拟合 reward）

- `baseline = V(s)`（这里的 `s` 取 Gate1 的特征 `feat1`）
- `critic_loss = MSE(reward, baseline)`

### 5.3 `critic_batch_mean`（兼顾：mean(length) + critic 拟合残差）

这是你“想同时生效”的版本，当前实现方式是：

1) 常数 baseline：`baseline_reward = -mean(length)`（标量）
2) critic 预测残差：`value_pred = V(s)`（向量 `[B]`）
3) 总 baseline：`baseline = baseline_reward + value_pred`
4) critic 训练目标是拟合残差：  
   `critic_loss = MSE(reward - baseline_reward, value_pred)`

这样做的含义是：

- batch mean baseline 负责“去掉 batch 级公共偏移”（很强、很稳定的方差降低项）
- critic 不需要拟合 reward 的绝对尺度，只需要拟合围绕 batch mean 的“个体偏差”（更容易学，也更稳）
- 两者在数学上不冲突：它们只是 baseline 的两部分（一个常数项 + 一个可学习项）

## 6. 特征提取（状态空间）：`1two_gate/features.py` + `1two_gate/paper_encoder.py`

### 6.1 Gate1 特征：`tsp_instance_features()`

输入：`coords: Tensor[B,N,2]`

默认（`FeatureConfig.extractor="paper"`）：

1) 用论文风格 encoder 得到图嵌入：`graph_emb = encoder(coords, mask)`
2) 追加规模特征：`scale = N`（作为 1 维常数拼到特征后面）
3) 输出：`[graph_emb || scale]`

mask 默认全 0（`_tsp_default_mask`），因为当前原型用固定 `N` 且不做 padding；接口仍保留 mask 参数，便于未来接入变规模数据。

### 6.2 Gate2 条件特征：`tsp_gate2_features()`

Gate2 的输入要体现 `data + sol0`。当前实现选择了“轻量、可跑通”的条件信息：

- `base = tsp_instance_features(coords, ...)`
- `+ length0`（`sol0.length`，形状 `[B,1]`）
- `+ tour0 的统计量`（来自 `tsp_tour_features`）

`tsp_tour_features(coords, tour)` 具体计算：

1) 按 tour 顺序 gather 出 `ordered_coords`
2) 计算相邻边长 `seg_len[i] = ||ordered[i] - ordered[i+1]||`
3) 输出四个统计量拼接：`mean/std/min/max`（形状 `[B,4]`）

因此 Gate2 的特征是：

`[graph_emb || scale || length0 || (edge_len_mean, edge_len_std, edge_len_min, edge_len_max)]`

### 6.3 “论文一致”编码器：`1two_gate/paper_encoder.py`

`1two_gate/paper_encoder.py` 是把作者选择器编码器的关键结构在 `1two_gate/` 下重写了一份，主要包含：

- `Naive_Encoder`：多层 self-attention + mask mean pooling
- `Encoder_h`：分层 encoder + downsampling pooling
  - 内部 block：`Encoder_block_h`
  - pooling/downsample：用额外 attention 层计算每个节点的 score，取 top `downsample_ratio` 的节点保留
- 组成层：`EncoderLayer`（MHA + FFN + Add&Norm）
- norm 支持：`batch / instance / rezero / none`（由 `FeatureConfig.paper_norm` 控制）

`1two_gate/features.py:build_paper_tsp_encoder()` 把 `FeatureConfig` 映射为 encoder 的 `model_params`，默认参数对齐 `neural-solver-selection/config_TSP.yml` 的那套选择器配置（但代码来源完全在 `1two_gate/` 内）。

## 7. 执行外部组件（动作落地）：`1two_gate/solver_zoo.py`

### 7.1 抽象：`SolutionBatch / Initializer / Iterator`

- `SolutionBatch`：统一表示解
  - `tour`：`Tensor[B,N]`
  - `length`：`Tensor[B]`
  - `reward` 属性：`-length`（与你的符号一致）
- `Initializer.solve(coords) -> SolutionBatch`
- `Iterator.improve(coords, sol0) -> SolutionBatch`

### 7.2 按 action 分组执行（关键工程点）

`run_initializers_by_action(coords, actions, zoo)` / `run_iterators_by_action(...)` 做了两件重要的事：

1) **把 batch 里选择同一个 action 的样本聚到一起**（减少重复调用 solver 组件）
2) **分别对每组样本调用对应 initializer/iterator**，然后把结果 scatter 回原 batch 的位置

这样，gate 的动作空间是离散的，但执行仍保持 batch 并行结构，便于训练稳定与速度可控。

### 7.3 初始化器封装：`NeuralARInitializer`

该 wrapper 直接调用 `EasyNCO/` 的 initialization pipeline：

- `state_td, _ = initialization.run(env, coords, decoder_strategy, "eval")`
- 从 `state_td` 取出：
  - `reward`：形状通常是 `[B,pomo]`
  - `selected_node_list`：形状通常是 `[B,pomo,N]`（有的版本放在 `state_td["next"]["selected_node_list"]`）
- 对每个实例选 `reward` 最大的那条轨迹作为最终 tour：
  - `best_idx = reward.max(dim=1).indices`
  - `best_tour = selected_node_list[batch_index, best_idx]`
  - `best_length = -best_reward`

这一步把不同 solver 内部的输出格式统一为 `SolutionBatch`，让 RL 只关心“tour + length”。

### 7.4 迭代器封装

- `NoIterationIterator`：对照/基线，直接返回 `sol0`
- `TwoOptIterator`（可选）：调用 `EasyNCO.neural_solvers.methods.difusco.util.two_opt_refine` 做确定性 2-opt；再用 `TSPEnv._get_travel_distance` 计算长度
- `RRCLIHStyleLEHDIterator`：一个最小化封装，把 `EasyNCO` 里的 LEHD RRC 思路跑通，并返回 per-instance 的最终 tour/length
  - 固定迭代步数：`for _ in range(max_steps): ...`
  - 每步：
    1) `env.load_problems(problems, batch_size)`
    2) destroy：随机截取一个 subpath，构造子问题（`_sampling_subpaths`），在 env 里设置 `env.solution/env.problems`
    3) repair：`env.reset()` + `policy.pre_forward()` + `env.pre_step()`，循环 `env.step(...)` 直到 done  
       - 前两步 action 被强制为解的尾节点与首节点（对齐该 RRC 过程）
       - 后续 action 由 `LEHDPolicy` 产生
    4) accept：如果 repair 后长度更短，则把 repaired subpath 回填到原解（`_accept_repaired_solution`）
  - 循环结束后，用 `env._get_travel_distance` 计算完整 tour length 并做 permutation 校验

这满足你提出的“先固定迭代次数，只选择迭代方式”。

## 8. 不改 `EasyNCO/` 的关键：`1two_gate/easynco_bootstrap.py`

`EasyNCO/` 本身就在仓库里，但为了避免直接触发平台中较重的初始化链路，你在 `1two_gate/` 里额外写了一个 bootstrap 层。它的作用不是“改目录名”，而是：

- `ensure_local_easynco()` 统一保证本地 `EasyNCO/` 可导入；
- 必要时补充 `sys.modules`、`__path__` 与轻量 package stub；
- 兼容少量 legacy import 与缺失的可选依赖。

同时，为了避免 `EasyNCO/` 的某些 `__init__.py` 在导入时拉入大量可选依赖（例如 torch_geometric / scipy / sklearn 等），你做了“轻量 stub”：

- `EasyNCO.data`：提供一个最小 `TSPGenerator` stub，保证 `TSPEnv` 导入路径可用，但不触发完整 data stack
- `EasyNCO.neural_solvers.methods`：把它变成一个空壳 package，避免执行其巨大 `__init__`；再按需填充 AM/POMO/LEHD 需要的少量导出符号
- `EasyNCO.neural_solvers.envs`：同样避免执行重的 `__init__`
- `EasyNCO.neural_solvers.backbones`：避免导入依赖 torch_geometric 的 GNN 部分，只填充 Transformer 相关符号
- 兼容旧导入：额外提供顶层 `neural_solvers` alias 指向 `EasyNCO/neural_solvers`（某些方法用 legacy import）

核心效果：`1two_gate/` 可以在“只用 AM/POMO/LEHD + TSP”时，把依赖范围尽量压小，并且**不改 `EasyNCO/`**。

## 9. 逐条对应你的“必须满足的要求”

1) **强化学习用 AC 架构**  
   - actor：`gate1/gate2`（`1two_gate/gates.py:build_mlp`）  
   - critic：`policy.value`（`1two_gate/gates.py:build_value_mlp`，按 `baseline` 模式可选启用）  
   - 训练：`loss = actor_loss + critic_coef * critic_loss`（`1two_gate/train_two_gate_tsp.py`）

2) **baseline = batch mean length**  
   - `baseline_length = length.mean()`，并转换为 `baseline_reward = -baseline_length`（`baseline="batch_mean"` 或 `critic_batch_mean` 都包含这一项）

3) **奖励函数用 score（路径长度）**  
   - `reward = -length`（`1two_gate/train_two_gate_tsp.py` 与 `1two_gate/solver_zoo.py:SolutionBatch.reward`）

4) **loss 不能忘记同时更新 Gate1 与 Gate2**  
   - `actor_loss = -mean((logp1 + logp2) * adv.detach())`：两个 gate 的 log-prob 直接相加，共享同一个 advantage

5) **固定迭代次数，只选择迭代方式**  
   - `RRCLIHStyleLEHDIterator(max_steps=cfg.rrc_steps)`（固定步数）  
   - Gate2 的动作只是在 `iter_zoo` 中选哪种 iterator（而不是学连续的迭代步数/时间分配）

另外，你的额外工程要求也满足：

- 初始化器/迭代器来自 `EasyNCO/`：`_build_initializer_zoo` / `_build_iterator_zoo` 直接 import EasyNCO 对应组件
- 尽量不修改 `EasyNCO/`：通过 `1two_gate/easynco_bootstrap.py` 做 alias/stub 实现“只调用不改动”
- 所有实现放在 `1two_gate/`：当前原型的新增代码都在 `1two_gate/` 目录下

## 11. 当前实现的边界与“框架优先”的取舍（事实描述）

- 当前只实现了 **TSP** 原型；数据来自在线随机生成（不读取 TSPLIB 等外部文件）。
- 默认不加载 solver policy checkpoint（如果不提供 `--*_ckpt`，求解器可能是随机初始化权重），因此性能不作为当前目标，重点是“框架跑通、信息流正确、loss 正确归因到两个 gate”。
- 评估阶段使用 greedy（`argmax`），训练阶段用采样（`Categorical.sample()`），探索主要来自 gate 的随机采样（以及可选的 solver 内部 sampling decoder）。
- 时间开销当前没有进入 reward/约束；迭代阶段用固定步数（`rrc_steps`），符合你“先不考虑时间”的阶段性设定。
