# 2l2r 运行说明

## 1. 任务定义

`2l2r` 做的是监督式 learning-to-rank：

- 输入：实例特征 + 候选 initialization methods
- 输出：每个 arm 的一个排序分数
- 训练：同一实例上的所有可行 arm 一起进入 ranking loss
- 推理：只在可行 arm 中选分数最大的那个

当前同时支持：

- `TSP`
- `CVRP`

并继续使用和 `2cmab2` 相同的：

- 数据构造协议
- 统一 arm 空间
- NSS 风格 encoder

## 2. 运行环境

服务器上建议使用：

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py ...
```

## 3. 常用命令

### 3.1 小规模 smoke test

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py \
  --epochs 1 \
  --batch-size 4 \
  --eval-batch-size 8 \
  --max-samples-per-problem 10 \
  --disable-progress \
  --output-dir 2l2r/outputs/smoke_test
```

### 3.2 默认 pairwise ranking

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py \
  --loss-name pairwise_logistic \
  --epochs 20 \
  --batch-size 32 \
  --eval-batch-size 64
```

### 3.3 listwise ranking

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py \
  --loss-name listwise_ce \
  --listwise-target-scale 8.0 \
  --epochs 20 \
  --batch-size 32 \
  --eval-batch-size 64
```

### 3.4 top1-focused 的 best-vs-all regret 训练

这是当前更推荐的方案。

它和前两种 ranking loss 的区别是：

- 不再主要优化“整张排序表”
- 而是直接优化“真实最优 arm 能不能压过其他 arm”
- 同时使用 normalized regret 给负样本加权
- 并默认用 `gain_vs_single_best_per_problem` 作为 best checkpoint 的选择标准

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py \
  --device cuda \
  --loss-name best_vs_all_regret \
  --hard-instance-weight-alpha 2.0 \
  --hard-instance-weight-cap 5.0 \
  --model-selection-metric gain_vs_single_best_per_problem \
  --epochs 20 \
  --batch-size 32 \
  --eval-batch-size 64
```

### 3.5 冻结底层 NSS encoder

```bash
conda run -n easynco_zhoucl python 2l2r/run_l2r.py \
  --freeze-encoder \
  --loss-name pairwise_logistic
```

## 4. 重要参数

- `--loss-name`
  - `pairwise_logistic`
  - `listwise_ce`
- `--pairwise-gap-weight`
  - pairwise 时是否按 reward gap 加权
- `--listwise-target-scale`
  - listwise 目标分布的锐度
- `--hard-instance-weight-alpha`
  - 对“single_best_per_problem 做不好的实例”加大训练权重
- `--hard-instance-weight-cap`
  - hard-instance 权重上限
- `--model-selection-metric`
  - `overall_mean_cost`
  - `gain_vs_single_best_per_problem`
- `--batch-size`
  - 训练 batch 大小
- `--eval-batch-size`
  - 验证/测试 batch 大小
- `--max-samples-per-problem`
  - 调试时每个问题最多取多少样本
- `--freeze-encoder`
  - 是否冻结底层 NSS 图编码器

## 5. 输出文件

一次运行结束后，输出目录里通常会有：

- `summary.json`
  - 最终 val/test 结果、baseline 对比、best checkpoint 路径
  - 如果是新方案，还会包含 `comparisons.val_vs_single_best_per_problem`
    和 `comparisons.test_vs_single_best_per_problem`
- `train_metrics.jsonl`
  - 每个优化 step 的 loss 日志
- `periodic_val.jsonl`
  - 周期性 val 指标
  - 新方案下会额外写出 `gains_vs_single_best_per_problem`
- `traces/selector_val_greedy.jsonl`
  - val 集逐实例预测详情
- `traces/selector_test_greedy.jsonl`
  - test 集逐实例预测详情
- `checkpoints/best.pt`
  - val mean cost 最优模型
- `checkpoints/final.pt`
  - 训练结束时最后模型

## 6. trace 中每条记录包含什么

`selector_test_greedy.jsonl` 中每条记录都会包含：

- 当前实例是谁：`problem / global_index / uid`
- 选中了哪个 arm：`selected_arm / selected_arm_name`
- 该 arm 的预测分数：`selected_score`
- 该 arm 的真实表现：`selected_reward / selected_cost`
- 该实例上的 oracle 最优 arm：`best_arm / best_cost`
- 所有 arm 的明细：`arm_details`

其中 `arm_details` 里每个 arm 会带：

- `score`
- `true_reward`
- `true_cost`
- `true_rank`
- `feasible`

这样后面可以直接复盘：

- 模型为什么选这个 arm
- 它和最优 arm 差在哪里
- 某个问题上模型是不是系统性偏向某几个方法
