# CVRP SOTA/经典启发式中的 Adaptive / Algorithm Selection：统一视角梳理

本文件把 `adaptive/notes/` 中 7 篇论文放到同一个坐标系下：**它们到底在“自适应地选择什么”？依据什么信号？怎么更新？作用在搜索 pipeline 的哪一层？**

> 目标：为你后续把“选择对象从 solver → pipeline 组件（init/iter）→ 更细粒度算子/参数”提供一个 OR 侧的对照组与设计空间。

## 1) 一句话对比表（选择对象）

| # | 论文 | 核心 adaptive/选择对象（最重要的那一个） | 更像 init/iter 哪一段 |
|---|------|------------------------------------------|------------------------|
| 1 | KGLS-VRP (2019) | **惩罚哪些结构**（边/组件）来改变搜索地形（GLS 的“选惩罚对象”） | Iter（改进器） |
| 2 | SISR (2020) | **删哪段字符串**（ruin 的“删谁/删多长/删在哪”）以释放 slack | Iter（邻域/破坏算子） |
| 3 | Accorsi&Vigo (2021) | **在不同规模/阶段切换搜索尺度**（小步精修 vs 大步跳坑/分解） | Iter（大规模改进器） |
| 4 | Hybrid adaptive ILS+DC (2021) | **选扰动算子/强度 + 多样性压力**（何时更强探索） | Iter（改进器调度） |
| 5 | POPMUSIC matheuristic (2021) | **选子问题 R + MIP 预算**（何时值得用精确优化） | Iter（强邻域/子问题专家） |
| 6 | AILS-II (2024) | **算子池权重自适应**（选哪个 perturbation/参数） | Iter（自适应 ILS） |
| 7 | HGS+SWAP* (2022) | **惩罚系数/可行率控制 + 多样性管理**（群体式闭环控制） | Iter（群体改进器） |

你会发现一个共同点：**adaptive 几乎都发生在 iteration 里**。初始化通常只要求“快且可行”，真正的性能来自迭代阶段的自适应调度与强邻域。

## 2) 把“adaptive”拆成三类：选算子、选参数、选子问题

### A) 算子选择（Operator / Neighborhood selection）

代表：AILS-II、（SISR 常作为一个 ruin 算子进入算子池）、Hybrid adaptive ILS。

- **动作空间**：`o ∈ O`（ruin/recreate、不同插入启发式、不同邻域块…）
- **反馈信号**：Δcost、是否找到新 best、耗时、可行率、停滞长度
- **更新规则**：权重/概率自适应（典型 ALNS：`w ← (1-ρ)w + ρ·score`）

这在你研究里几乎可以直接映射为：“Gate2 选择迭代组件/邻域组件”，而且 reward 更密集（每次迭代都有信号），不需要离线全组合标注。

### B) 参数控制（Parameter / Penalty / Diversification control）

代表：HGS 的惩罚系数自适应（维持目标可行率）、Hybrid adaptive ILS 的扰动强度与多样性压力、Accorsi&Vigo 的规模化预算控制。

- **动作空间**：连续参数（扰动强度 k、候选集大小、惩罚系数 α/β、接受阈值、预算…）
- **反馈信号**：可行率、收敛程度、多样性指标、时间/质量折中
- **更新规则**：闭环控制（目标区间）或基于停滞的阶段性调参

这类 adaptive 的关键特点是：**它不需要“懂问题语义”的学习模型也能工作**，因为很多反馈信号是通用的（停滞、可行率、多样性）。

### C) 子问题选择（Subproblem selection / Decomposition selection）

代表：POPMUSIC matheuristic。

- **动作空间**：子结构 `R`（选哪几条路线/哪些客户集合）、以及 MIP 预算
- **反馈信号**：子问题 ROI（Δcost/time）、停滞、结构潜力 proxy
- **更新规则**：优先队列/权重自适应/预算自适应

这类方法天然契合你“组件组合”的主题：不同 `R` 的定义本质上就是不同“迭代组件”的组合与调度。

## 3) “Algorithm selection”在 OR 里通常长什么样？

和你现在做的“实例 → 选 solver”相比，这些 OR 启发式的 selection 往往更“在线”和更“局部”：

- **选择频率更高**：每一次扰动/每一轮迭代都在选；
- **反馈更直接**：Δcost、是否可行、耗时；
- **动作更细粒度**：选择算子/参数/子问题，而不是直接选一个黑盒 solver。

因此在“学习”层面，它们更像 bandit/RL 的天然场景，而不是监督分类。

## 4) 对你做“init+iter 组合有效性”的启发总结

1. **理论可行性很强**：这些方法普遍把 iteration 设计成 `f(instance, solution) -> improved_solution`，不依赖解的来源；因此“换初始化器”在原理上总是可行。
2. **组合有效性的来源**：不同 iteration/邻域相当于不同搜索邻域族；组合=扩大可达改进集合（邻域并集），因此很容易出现“对某些实例更互补”的现象。
3. **更细粒度的组合比“换 solver”更自然**：OR 里广泛存在“在一个方法内部自适应地组合多个算子/参数/子问题”的传统，这为你把选择对象下钻到 init/iter、甚至下钻到“删哪段/删多长/用哪个邻域”提供了经典先例。
