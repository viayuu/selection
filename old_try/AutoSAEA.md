# AutoSAEA 论文与代码详解

## 1. 先给一个总览

如果只用一句话概括，`AutoSAEA` 做的事情是：

> 在“昂贵优化”里，每次真实评估都非常贵，所以它先用便宜的替代模型来猜哪里可能好，再用一个两层老虎机策略，动态决定“这轮该用哪种替代模型 + 该用哪种选点规则”。

它不是在学一个很大的神经网络策略，也不是一次性离线挑出一个固定方法永远不变。  
它是在**一次优化运行过程中，在线地、逐轮地选择 surrogate model 和 infill criterion**。

更具体地说，AutoSAEA 每轮都要做三件事：

1. 先从 4 种 surrogate model 里选 1 种。
2. 再从与该模型兼容的 2 种 infill criterion 里选 1 种。
3. 用这个“模型 + 选点规则”的组合，提出一个新候选点，做一次真实昂贵评估，然后根据结果更新选择偏好。

所以 AutoSAEA 的核心不是“发明了一个新 surrogate model”，而是：

- 把**模型选择**和**选点规则选择**统一起来；
- 把它们建模成一个**两层多臂老虎机问题**；
- 用 **TL-UCB** 决定怎么选；
- 用 **TL-R** 决定怎么奖惩。

## 2. 先补基础概念

因为你说自己对 EOP、SAEA、老虎机这些都不太熟，我先把这些概念讲清楚。

### 2.1 什么是 EOP

EOP 是 `Expensive Optimization Problem`，中文常叫：

- 昂贵优化问题
- 高代价优化问题

“昂贵”不是说数学公式很长，而是说：**算一次真实目标函数值很贵**。

比如：

- 跑一次流体仿真要几十秒甚至几小时
- 跑一次油藏数值模拟很慢
- 做一次真实实验要花材料、时间和金钱

于是问题就来了：

- 普通进化算法通常要评估很多很多个候选解
- 但在 EOP 里，你没有那么多预算

所以在 EOP 里，最珍贵的资源通常不是 CPU 的小运算，而是：

- `FE = Function Evaluation`
- 也就是真实目标函数调用次数

论文里几乎所有设计都围绕这个核心约束：

> 尽量少做真实 FE，但仍尽量找到好解。

### 2.2 什么是 EA

EA 是 `Evolutionary Algorithm`，进化算法。

它的直觉很简单：

- 手里先有一批候选解
- 根据当前好的解，变异、交叉，生成新解
- 比较新老解质量
- 一代一代往前改进

AutoSAEA 里底层用到的生成候选解方式主要是 `DE = Differential Evolution`。

你可以先把 DE 理解成：

- 它会看当前好的点
- 也看几个随机点之间的差分方向
- 用这些方向来合成新候选点

### 2.3 什么是 surrogate model

surrogate model 就是：

- 替代模型
- 代理模型
- 近似模型

它的作用是：**用一个便宜模型去近似昂贵目标函数**。

直觉上就像：

- 真实函数很贵，像“真老师”
- surrogate model 很便宜，像“助教的快速估分器”

助教不一定每次都完全正确，但估一个分数很快。  
于是你就可以：

- 先让 surrogate model 大量快速预测
- 再只挑少数最值得怀疑/最值得期待的点做真实评估

### 2.4 什么是 SAEA

SAEA 是 `Surrogate-Assisted Evolutionary Algorithm`，替代模型辅助进化算法。

它的基本套路是：

1. 先收集一小批真实评估数据
2. 用这些数据训练 surrogate model
3. 用 surrogate model 指导搜索
4. 只对很少的新点做真实 FE
5. 把新 FE 再加入数据集
6. 重复上面过程

所以 SAEA 的本质不是把 EA 换掉，而是：

> 在 EA 外面套一层“便宜预测器”，用来节省真实评估次数。

### 2.5 什么是 infill criterion

这是理解论文的关键。

很多人第一次看 SAEA 时，会以为：

- surrogate model 决定一切

其实不是。

surrogate model 只回答一个问题：

- “这个点看起来大概怎么样？”

但真正决定“下一次真实 FE 评估谁”的，往往是另一个东西：

- `infill criterion`
- 中文可以理解成“填充准则”“选点评分规则”“采样准则”

它回答的问题是：

- “在 surrogate model 给出的信息下，下一个最值得真实评估的点是谁？”

所以你可以这样理解：

- surrogate model = 负责“预测”
- infill criterion = 负责“决策”

论文正是抓住了这一点：

> 一个模型配不同的 infill criterion，行为会完全不同。

例如同样是 GP：

- 配 LCB，会更强调“均值低 + 不确定性高”的点
- 配 EI，会更强调“预计能改进当前最优值”的点

因此，**模型和 infill criterion 是耦合的**，不能只选其一。

### 2.6 什么是 exploration 和 exploitation

几乎所有优化、强化学习、老虎机问题都会遇到这组矛盾：

- `exploration`：探索，去试试还不熟悉但可能更好的区域
- `exploitation`：开发，继续深挖当前看起来已经很好的区域

在这篇论文里：

- 如果太探索，可能浪费 FE 在不太靠谱的地方
- 如果太开发，可能早早陷进局部最优

不同 surrogate + infill 组合，本质上就在提供不同的探索/开发平衡。

### 2.7 什么是老虎机，多臂老虎机，多臂老虎机的 UCB

“老虎机”对应的是 `Multi-Armed Bandit, MAB`。

直觉版本如下。

想象你面前有很多台老虎机：

- 每台都可能赚钱
- 但你事先不知道哪台平均回报最高

你每轮只能拉一台。  
所以你必须平衡两件事：

- 多拉目前看起来收益高的机器
- 也要偶尔试试还没怎么拉过的机器

这就是 MAB。

在 AutoSAEA 里：

- 不是让你选真实赌场机器
- 而是让你选“哪种模型/哪种准则组合最值得信任”

#### UCB 是什么

UCB 是 `Upper Confidence Bound`。

它的经典思想特别朴素：

- 一个 arm 的历史平均奖励高，说明它过去表现好
- 一个 arm 被选次数少，说明我们对它还不够了解，应该给它一点探索加成

所以 UCB 常写成：

`历史平均奖励 + 探索奖励`

论文中的形式就是：

`Q + sqrt(alpha * ln(t) / T)`

其中：

- `Q` 是当前估计价值
- `T` 是这个 arm 被选过多少次
- `t` 是总轮数
- `alpha` 控制探索强度

含义是：

- `Q` 大，倾向多选
- `T` 小，探索项大，也倾向多选

所以 UCB 的核心精神是：

> 偏爱“历史表现好”或“虽然不确定但值得继续试”的 arm。

## 3. 论文到底在解决什么问题

### 3.1 论文的出发点

作者的观察是：

1. 固定单一 surrogate model 的 SAEA 泛化性差  
   不同问题地形差异很大，一个模型未必都能拟合好。

2. 同时上很多模型做集成，虽然更稳，但开销也更大  
   而且有些模型其实并不适合当前问题，等于白白消耗时间。

3. 现有 adaptive SAEA 往往只做一半  
   有的只自适应选模型，不选 infill criterion；有的只选 infill criterion，不选模型。

但实际里：

- surrogate model 和 infill criterion 是强耦合的
- 两者共同决定“这轮会选出什么点”
- 因而也共同影响优化效果

所以作者想做的是：

> 不只自适应选模型，也不只自适应选准则，而是把两者放在一个层次化框架里联合选择。

### 3.2 AutoSAEA 的核心思想

论文把模型和 infill criterion 的联合选择，建成一个**两层多臂老虎机**：

- 第一层 arm：选 surrogate model
- 第二层 arm：在所选 surrogate model 下，再选兼容的 infill criterion

这就是论文中的：

- `TL-MAB = Two-Level Multi-Armed Bandit`

作者使用：

- `TL-UCB` 做选择
- `TL-R` 做奖励传播

## 4. AutoSAEA 的方法细讲

### 4.1 四种 surrogate model

论文使用 4 种高层 arm，也就是 4 类 surrogate model。

#### 1. GP

`GP = Gaussian Process`

特点：

- 不仅能预测均值
- 还能给出不确定性

这很重要，因为很多 infill criterion，比如：

- LCB
- EI

都需要用到“不确定性”。

直觉上，GP 很适合：

- 样本不多时
- 需要同时考虑“预测值”和“不确定性”时

代价是：

- 通常比 RBF、PRS 更重一些

#### 2. RBF

`RBF = Radial Basis Function`

特点：

- 常见
- 速度快
- 在很多连续优化任务里很实用

直觉上，RBF 更像：

- 一个比较实用的函数插值器
- 不一定给你概率不确定性
- 但拟合和预测效率不错

#### 3. PRS

`PRS = Polynomial Response Surface`

论文代码默认是二次多项式响应面。

直觉上，PRS 适合：

- 维度不太高
- 地形相对平滑
- 局部可以被低阶多项式近似的情况

如果问题地形特别复杂、多峰、扭曲严重，PRS 往往就不如更灵活的模型。

#### 4. KNN

`KNN = K-Nearest Neighbor`

这里它不是拿来做精确回归，而是做**分类**。

做法是：

- 把当前种群按 fitness 排成若干等级
- 训练一个 KNN 分类器
- 预测新候选点属于哪个等级

所以 KNN 在这里更像是在回答：

- “这个点更像优质区域，还是一般区域？”

而不是：

- “这个点的精确函数值是多少？”

### 4.2 八个组合 arm

高层 4 种模型，每种模型有对应的低层 infill criterion，于是形成 8 个合法组合。

| 组合 arm | 含义 | 倾向 |
| --- | --- | --- |
| GP + LCB | 用 GP 预测均值和方差，用 LCB 选点 | 探索与开发平衡 |
| GP + EI | 用 GP 预测均值和方差，用 EI 选点 | 更关注期望改进 |
| RBF + prescreening | 用 RBF 给一批候选点打分，挑预测最优者 | 快速筛选 |
| RBF + local search | 直接在 RBF surrogate 上做局部优化 | 偏开发 |
| PRS + prescreening | 用 PRS 给候选点打分，挑预测最优者 | 快速筛选 |
| PRS + local search | 在 PRS surrogate 上做局部优化 | 偏开发 |
| KNN + L1-exploitation | 先找被判为优质区域的点，再选更贴近优秀样本簇的点 | 更保守开发 |
| KNN + L1-exploration | 先找被判为优质区域的点，再选离优秀样本簇更远的点 | 在优质区域里做探索 |

### 4.3 各种 infill criterion 到底是什么意思

#### 4.3.1 GP 的两个准则：LCB 和 EI

##### LCB

`LCB = Lower Confidence Bound`

形式大致是：

`预测均值 - w * 预测标准差`

其中：

- 预测均值低，说明可能本来就好
- 标准差大，说明模型不确定，也许藏着更好点

所以 LCB 会偏好：

- 均值低的点
- 或者虽然均值不算最低，但不确定性很高的点

这就是一种典型的探索/开发折中。

##### EI

`EI = Expected Improvement`

它问的是：

> 相对当前最优值，这个点“期望能改进多少”？

所以 EI 会偏向：

- 预测值可能比当前最好还好
- 并且这种改进概率和改进幅度综合起来比较可观

#### 4.3.2 RBF/PRS 的两个准则：prescreening 和 local search

##### Prescreening

做法是：

1. 先用 DE 生成一批候选点
2. 用 surrogate model 给这一批点全部打分
3. 只挑 surrogate 预测最好的那个点去做真实 FE

所以 prescreening 的特点是：

- 便宜
- 简单
- 相当于“先筛一轮再送审”

##### Local search

做法是：

1. 先拟合 surrogate model
2. 再直接在 surrogate 上做一次局部优化
3. 找 surrogate 眼中最好的点
4. 对该点做真实 FE

它和 prescreening 的区别是：

- prescreening 是“在一批现成候选里挑最好的”
- local search 是“直接在 surrogate 面上继续搜一个更优点”

所以 local search 更像：

- 在当前已知好区域里做深挖

#### 4.3.3 KNN 的两个准则：L1-exploitation 和 L1-exploration

KNN 这部分最容易看懵。

论文做法是：

1. 先把当前种群按 fitness 排序
2. 分成 `L=5` 个等级
3. 最好的那一层叫 `L1`
4. 用 KNN 预测新候选点是不是属于 `L1`

于是先从候选集中筛出：

- “看起来像 L1 的点”

然后再分两种选法。

##### L1-exploitation

在这些被预测为 `L1` 的点里，选一个：

- 和当前优秀样本簇更接近的点

所以它更像：

- 朝着已经确认好的区域再扎深一点

##### L1-exploration

在这些被预测为 `L1` 的点里，选一个：

- 和当前优秀样本簇更远的点

所以它更像：

- “虽然还是优质区域，但别老挤在同一块，去远一点的新位置看看”

这是一种“在优质区域内部继续探索”的思路。

### 4.4 为什么要用两层老虎机，而不是直接把 8 个组合平铺成 8 个 arm

这是论文最关键的设计点之一。

如果直接把 8 个组合都当成平级 arm，也不是不行。  
但作者认为两层结构更合理，因为：

1. surrogate model 是更高层的决策  
   它先决定这轮你打算怎么“看待问题”。

2. infill criterion 是在该模型下的更细粒度决策  
   它决定你如何“利用这个模型的输出”。

3. 奖励可以从低层往高层传播  
   如果某个低层准则持续表现好，就能反过来提升其所属模型的价值。

也就是说：

- 低层 arm 负责更具体的行为差异
- 高层 arm 负责更抽象的方法偏好

这个结构比“8 个 arm 完全平铺”更有层次感。

### 4.5 TL-UCB：两层选择机制

论文里的 TL-UCB 分两步。

先把论文里的两个核心公式直接写出来。

高层选择公式：

`a_t^H = arg max_{a in A^H} [ Q_a^H(t) + sqrt(alpha * ln(t) / T_a^H(t)) ]`

低层选择公式：

`a_t^L = arg max_{a in A_{a_t^H}^L} [ Q_a^L(t) + sqrt(alpha * ln(t) / T_a^L(t)) ]`

如果第一次看这两个式子，很容易只看到一堆符号。  
其实它们的结构非常统一，都是：

`当前估计价值 + 探索奖励`

也就是说，TL-UCB 的本质没有变复杂，它只是把普通 UCB 拆成了两层：

1. 先在高层做一次 UCB，决定“这一轮相信哪类 surrogate model”
2. 再在这个 model 下面做一次 UCB，决定“这一轮在这个 model 下面用哪种 infill criterion”

#### 4.5.1 高层公式里的每个符号到底是什么意思

先看高层公式：

`a_t^H = arg max_{a in A^H} [ Q_a^H(t) + sqrt(alpha * ln(t) / T_a^H(t)) ]`

这里每个量可以这样理解。

- `a_t^H`
  第 `t` 轮最终被选中的高层 arm，也就是 surrogate model。

- `A^H`
  高层 arm 集合。论文里就是 4 个模型：
  `GP, RBF, PRS, KNN`。

- `Q_a^H(t)`
  到第 `t` 轮为止，算法对高层 arm `a` 的“当前价值估计”。
  你可以把它理解成：
  “这个 surrogate model 最近整体上靠不靠谱？”

- `T_a^H(t)`
  到第 `t` 轮为止，高层 arm `a` 被选中过多少次。

- `ln(t)`
  总轮数越往后，探索项增长得越慢。
  用对数而不是线性，是因为：
  论文不希望随着时间推移还一直大幅度鼓励探索，而是希望探索逐渐减弱。

- `alpha`
  控制探索强度的超参数。
  `alpha` 越大，探索项越大，算法越愿意去试那些还没被充分尝试的 arm。

- `arg max`
  表示不是取这个值本身，而是取“让这个值最大的那个 arm”。

于是这个式子整体上就在说：

> 高层 arm 的得分 = 目前看起来有多好 + 因为还没被试够而应得的探索补偿。

#### 4.5.2 为什么探索项长成 `sqrt(alpha * ln(t) / T)`

这个结构的直觉非常重要。

先看分母 `T_a^H(t)`：

- 如果某个 arm 已经被试了很多次，说明我们对它已经比较了解
- 那么它就不需要很强的“探索加成”
- 所以 `T` 越大，探索项越小

再看分子 `ln(t)`：

- 随着总轮数 `t` 增大，所有 arm 的探索需求都会缓慢上升
- 但上升得很慢，因为是对数

再看最外层的平方根：

- 它会让探索项衰减得更平滑
- 避免探索奖励过大，压过价值项

所以这个式子的行为是：

1. 一个 arm 如果均值奖励高，即使探索项不大，也容易被选
2. 一个 arm 如果均值奖励一般，但长期没试，探索项会上来，仍有机会被重新尝试
3. 一个 arm 如果奖励差且也试了很多次，它的 UCB 会越来越没有竞争力

这就实现了：

- exploitation：优先用最近表现好的 arm
- exploration：偶尔给冷门 arm 重新证明自己的机会

#### 4.5.3 低层公式为什么只在关联子集里选

再看低层公式：

`a_t^L = arg max_{a in A_{a_t^H}^L} [ Q_a^L(t) + sqrt(alpha * ln(t) / T_a^L(t)) ]`

这里和高层公式最大的不同是：

- 选取范围不是整个 `A^L`
- 而是 `A_{a_t^H}^L`

它表示：

- 只在“和当前高层 model 兼容的低层 arm 集合”里选

例如：

- 如果高层选中的是 `GP`
- 那低层只在 `LCB` 和 `EI` 中选

而不会去选：

- `RBF local search`
- `KNN L1-exploration`

因为这些不是 `GP` 的子 arm。

这就是“hierarchical”最关键的地方：

- 低层不是全局自由竞争
- 而是受高层父节点约束

#### 4.5.4 一个完整的数值直觉例子

假设现在到了第 `t = 30` 轮。

高层 4 个模型当前状态如下：

- `GP`: `Q = 0.62`, `T = 10`
- `RBF`: `Q = 0.58`, `T = 4`
- `PRS`: `Q = 0.50`, `T = 12`
- `KNN`: `Q = 0.55`, `T = 4`

又假设 `alpha = 2.5`。

那你不用精确手算也能看出：

- `GP` 的价值最高，但被试过不少次
- `RBF` 和 `KNN` 的价值略低，但因为 `T` 小，探索项更大
- `PRS` 价值不高、尝试次数又不少，所以吸引力会偏低

于是这时候：

- 如果 `GP` 的高价值仍压得住探索项，它会被选
- 如果 `RBF` 或 `KNN` 因探索补偿而反超，它们也可能被选

然后假设高层选中了 `RBF`，接下来只需要比较：

- `RBF + prescreening`
- `RBF + local search`

也就是在 RBF 的两个子 arm 之间再做一次同样逻辑的 UCB 比较。

#### 4.5.5 TL-UCB 的真正作用

TL-UCB 做的不是“保证每一轮都选最好方法”，因为最好方法本来就未知。  
它真正做的是：

> 在有限真实 FE 预算下，尽量把尝试次数更多分配给“最近更有希望”的模型和准则组合，同时又不完全放弃对其他组合的试探。

#### 第一步：选 surrogate model

对 4 个高层 arm 分别计算：

`高层价值 + 高层探索项`

谁最大选谁。

#### 第二步：在所选模型下选 infill criterion

例如如果第一步选中了 GP，那么第二步只在：

- GP + LCB
- GP + EI

这 2 个低层 arm 之间做 UCB 选择。

而不会去拿 `GP` 和 `RBF local search` 直接比，因为那不是一个“同一父节点下”的关系。

### 4.6 TL-R：两层奖励机制

这是论文另一个核心。

如果说 TL-UCB 解决的是“怎么选”，那么 TL-R 解决的就是：

> 选完之后，应该如何根据这次结果给高层 arm 和低层 arm 记账？

论文里的 TL-R 不是一个普通的“成功就加 1、失败就加 0”的粗糙奖励，而是一个层次化奖励传播机制。

#### 4.6.1 低层奖励

作者不用“真实 fitness 改进幅度”直接做低层奖励，而是用：

- 新候选点在当前种群里的**名次**

具体公式是：

`reward = (N + 1 - rank) / N`

其中：

- `N` 是种群大小
- `rank = 1` 表示新点最好
- `rank = N+1` 表示新点比当前种群所有点都差

这样做有几个好处：

1. 奖励天然落在 `[0,1]`
2. 不同问题尺度下更稳定
3. 比“只有打破全局最优才给奖励”更不稀疏
4. 只要新点还不错，就能给连续反馈

##### 一个简单例子

如果当前种群大小 `N=100`：

- 新点排第 1，奖励就是 `1.00`
- 新点排第 10，奖励就是 `0.91`
- 新点排第 50，奖励就是 `0.51`
- 新点排第 101，奖励就是 `0`

所以这个奖励本质是在说：

> 你这次选的点，在“当前最好的 100 个点”里到底算不算优秀。

##### 把公式 (24) 逐项拆开看

论文原式是：

`r_{a_t^L} = -(1/N) * I(x_t) + (N+1)/N`

其中：

- `r_{a_t^L}`
  本轮被选中的低层 arm 的奖励

- `N`
  当前 population 大小

- `I(x_t)`
  新候选点 `x_t` 插入当前 population 后的名次

这个式子其实就是一条直线。

把它改写一下更直观：

`r_{a_t^L} = (N + 1 - I(x_t)) / N`

你立刻就能看出：

- 名次越小，也就是排名越靠前，奖励越大
- 名次越大，也就是越差，奖励越小

所以这不是一个神秘公式，而是一个非常朴素的“排名线性映射”。

##### 为什么论文不用“fitness 改进值”而用“排名”

这是论文里很有意思的设计。

如果用“真实改进量”做奖励，会遇到几个问题：

1. 不同问题尺度差异很大  
   有的问题目标值是几百，有的是几万，有的是负值，直接用改进量不稳定。

2. 奖励可能非常稀疏  
   如果只有明显打破当前最好值时才有高奖励，bandit 更新会很慢。

3. 极端大改进会把奖励尺度拉爆  
   某一轮偶然特别好，可能让某个 arm 的统计量失真。

而“排名奖励”的好处是：

- 统一落在 `[0,1]`
- 跨问题更稳定
- 每一轮几乎都能产生反馈
- 不依赖问题原始数值尺度

所以论文不是说改进量不重要，而是说：

> 对 bandit 来说，排名反馈更稳定、更密集、更适合在线更新。

##### 低层价值更新公式 (25) 是什么意思

论文接着给出：

`Q_{a_t^L}^L(t+1) = [ T_{a_t^L}^L(t) * Q_{a_t^L}^L(t) + r_{a_t^L} ] / [ T_{a_t^L}^L(t) + 1 ]`

这个式子本质上就是：

> 历史平均值的增量更新。

把它翻译成人话：

- 过去这个低层 arm 被选了 `T` 次
- 过去的平均奖励是 `Q`
- 这次新得到一个奖励 `r`
- 那么更新后的新平均值就是“旧总和加新奖励，再除以新次数”

举个例子。

如果某个低层 arm 过去：

- 被选过 `4` 次
- 平均奖励是 `0.50`

那么它过去的奖励总和就是：

- `4 * 0.50 = 2.0`

如果这次新奖励是：

- `0.80`

那更新后：

- 新总和 = `2.0 + 0.8 = 2.8`
- 新次数 = `5`
- 新均值 = `2.8 / 5 = 0.56`

这就是式 (25) 在干的事。

#### 4.6.2 高层奖励

高层奖励不是直接看 candidate 的 fitness，而是看：

- 对应低层 arm 的价值有没有上升

如果低层 arm 的均值奖励变大了，说明：

- 在这个 surrogate model 下，这个 infill criterion 最近更靠谱了

于是高层 model 也应该得到正反馈。

论文进一步证明后可以得到：

> 高层 arm 的值，本质上等于其关联低层 arm 值的平均数。

这点非常重要，因为它解释了“为什么高层值可以由低层表现自然涌现出来”。

##### 先看高层奖励公式 (26)

论文给出的高层奖励是：

`r_{a_t^H} = [ Q_{a_t^L}^L(t+1) - Q_{a_t^L}^L(t) ] / |A_{a_t^H}^L|`

这个式子第一次看容易抽象，但其实意思很直接：

- 如果本轮选中的低层 arm 更新后变得更好
- 那么它所属的高层 model 也应该得到正反馈

这里每个量的含义是：

- `Q_{a_t^L}^L(t+1) - Q_{a_t^L}^L(t)`
  这次低层 arm 的价值增量

- `|A_{a_t^H}^L|`
  当前这个高层 arm 下面一共有多少个低层子 arm

为什么要除以这个数量？

因为作者希望高层奖励的传播是“平均化”的，而不是让一个低层 arm 的波动直接把整个高层价值拉得过大。

在本文设置里，每个 model 都关联 2 个低层 arm，所以这里实际常常是在除以 `2`。

##### 再看高层价值更新公式 (27)

接着论文写：

`Q_{a_t^H}^H(t+1) = Q_{a_t^H}^H(t) + r_{a_t^H}`

这表示：

- 如果低层价值上升，高层价值就上升
- 如果低层价值下降，高层价值就下降

也就是说，高层 arm 并不是直接根据真实 candidate 排名获得奖励，而是：

> 通过它所选中的低层 arm 的表现变化，间接获得奖励。

这是 TL-R 最精妙的地方：

- 低层 arm 直接对 candidate 负责
- 高层 arm 对低层 arm 的长期整体表现负责

##### 为什么论文说高层值等于其子 arm 值的平均

论文后面的式 (28) 到 (30) 本质是在证明：

> 如果初始化时高层值和低层值的关系设好，那么以后每一轮更新后，高层值始终等于其所有子低层值的平均数。

这件事非常重要，因为它说明：

- 高层不是另起一套完全独立的奖励系统
- 高层价值不是拍脑袋定义的
- 它是由低层表现自然汇总出来的

所以你可以这样理解高层价值：

- `GP` 的高层价值，不是“GP 这轮好不好”的单次评价
- 而是“GP 下面那两个低层策略，整体来看现在值不值得信任”

##### 一个具体数值例子

假设当前高层 arm 是 `GP`，它有两个低层子 arm：

- `GP + LCB`
- `GP + EI`

假设这时：

- `Q(GP+LCB) = 0.40`
- `Q(GP+EI) = 0.60`

那么根据论文，高层 `GP` 的值就是：

- `Q(GP) = (0.40 + 0.60) / 2 = 0.50`

现在这轮选中了 `GP + LCB`，并且更新后：

- `Q(GP+LCB)` 从 `0.40` 变成 `0.48`

那么它的增量就是：

- `0.08`

由于 `GP` 有 2 个子 arm，所以高层奖励是：

- `0.08 / 2 = 0.04`

于是高层值更新成：

- `0.50 + 0.04 = 0.54`

而新的子 arm 平均数也正好是：

- `(0.48 + 0.60) / 2 = 0.54`

这就直观展示了论文推导为什么成立。

### 4.7 AutoSAEA 整体优化流程

把论文方法串起来，一轮完整流程是这样的。

#### 初始化阶段

1. 用 `LHS = Latin Hypercube Sampling` 在搜索空间里采 100 个初始点
2. 对这 100 个点做真实 FE
3. 建立数据库 `D`
4. 把所有 arm 的值和选择次数初始化
5. 前 8 轮强制每个合法组合 arm 至少试一次

#### 主循环阶段

每一轮：

1. 从数据库 `D` 中取当前最好的 `N=100` 个点，组成当前种群 `P`
2. 用 TL-UCB 先选 surrogate model，再选 infill criterion
3. 用这个组合产生一个新候选点 `x_t`
4. 对 `x_t` 做一次真实 FE
5. 把 `x_t` 加入数据库
6. 根据它在当前种群中的排名，更新低层奖励
7. 再把低层更新传播到高层
8. 重复直到 FE 预算耗尽

所以整个算法有一个非常清楚的节奏：

- 大量便宜 surrogate 预测
- 每轮只做 1 次昂贵真实 FE
- 用这 1 次 FE 的结果更新 bandit 偏好

## 5. 论文实验结果怎么理解

### 5.1 用了哪些实验

论文主要做了三部分：

1. `CEC2005` benchmark，10 维和 30 维
2. `CEC2015` benchmark，10 维和 30 维
3. 一个真实油藏生产优化问题

在 benchmark 上：

- 总 FE 预算是 1000
- 每个问题独立运行 20 次

评价指标是：

- 找到的最优值与真实最优值之间的误差

统计检验用了：

- Wilcoxon rank-sum test
- Friedman test with Hommel post-hoc

### 5.2 论文结论

作者的主要结论是：

1. AutoSAEA 在大多数 benchmark 上优于或至少不差于多个已有 SAEA。
2. 相比只固定单一模型/单一准则的方法，它更稳。
3. 相比只自适应选模型或只自适应选准则的方法，它的联合选择更有效。
4. 在真实油藏生产优化问题上，它的平均表现也最好或接近最好。

### 5.3 论文最想证明的不是“某个 arm 永远最好”

这一点很关键。

论文最想证明的是：

> 不同问题、不同优化阶段，最适合的 surrogate model 和 infill criterion 不一样。

作者在自适应行为分析里展示了：

- 某些问题前期更偏好一种模型，后期又切换到另一种
- 有些问题上 GP 更常被选
- 有些问题上 PRS 或 RBF 会更有优势

也就是说，AutoSAEA 不是想证明：

- “GP 永远最好”
- “RBF 永远最好”
- “EI 永远最好”

而是想证明：

> 在线自适应选择，比预先押注某一个固定组合更合理。

## 6. 我对论文的通俗理解

如果把整篇论文“翻译成人话”，它其实是在说：

1. 昂贵优化里，真实 FE 太贵，所以要靠 surrogate model 帮忙。
2. 但 surrogate model 本身不是万能的，不同问题对不同模型友好程度不同。
3. 而且同一个 model，配不同 infill criterion，选点风格也差很多。
4. 所以不要提前拍脑袋固定一个组合。
5. 最好在运行中边做边学：  
   哪个组合最近有效，就多给它机会；哪个组合最近不灵，就少给它机会。

这其实是一种**在线算法配置**思想。

从更高层看，AutoSAEA 不是在优化“解”本身，而是在同时优化：

- 问题解
- 以及当前这轮该用什么搜索策略

## 8. 代码运行流程详解

### 8.1 `run_myexperiment.m` 在做什么

这份脚本是最外层总控。

它做了几件事：

1. 定义测试问题集合  
   包括 15 个 `CEC05_f1 ~ CEC05_f15` 和 15 个 `CEC15_f1 ~ CEC15_f15`

2. 定义维度  
   只跑 `10` 和 `30`

3. 定义运行次数  
   `Runs = 20`

4. 逐个问题、逐个维度调用 `RUN_AutoSAEA`

代码里还能看到：

- `f_bias_set`
- `f_bias_set2`

它们是 benchmark 已知最优值的偏移量，用于之后计算 function error。

### 8.2 `RUN_AutoSAEA.m` 在做什么

这份文件是“单个问题，多次独立重复运行”的包装器。

它会：

1. 循环 `runs` 次
2. 每次调用 `AutoSAEA(FUN, D, LB, UB)`
3. 记录每次 run 的 best-so-far 曲线
4. 计算均值、中位数、标准差、平均收敛曲线
5. 最后保存到 `result/` 目录

这里 `gsamp1(r,:) = gfs(1:mf);` 的含义是：

- 记录第 `r` 次运行在每个 FE 时刻的 best-so-far 值

所以如果以后你想画收敛曲线，核心数据基本就在这里。

### 8.3 `AutoSAEA.m` 是真正的核心

这份文件基本对应论文里的 Algorithm 1。

它的初始化参数是：

- `F = 0.5`
- `CR = 0.9`
- `apha = 2.5`
- `level = 5`
- `initial_sample_size = 100`
- `MaxFEs = 1000`

这和论文的典型设定是一致的。

#### 8.3.1 初始化阶段

主程序首先用：

- `lhsdesign(initial_sample_size, D)`

产生 100 个初始点，然后对每个点做真实 FE。

此时维护的几个关键变量是：

- `hx`：历史上所有真实评估过的点
- `hf`：对应的真实 fitness
- `CE`：记录 `(NFE, fitness)`，更偏日志用途
- `gfs`：每个 NFE 时刻的 best-so-far 值

所以从概念上看：

- `hx/hf` 就是论文里的数据库 `D`
- `gfs` 是为了画收敛曲线

#### 8.3.2 当前种群怎么取

每轮循环开始时，代码会：

1. 对 `hf` 排序
2. 取最好的前 `gs=100` 个点

得到：

- `ghx`：当前种群的位置
- `ghf`：当前种群的 fitness

这和论文写的“从数据库中取 N 个最好点作为当前 population”完全一致。

#### 8.3.3 前 8 轮做什么

前 8 轮代码不是通过一个显式 `CA` 数组来调度，而是直接写成了 8 个 `if/elseif` 分支，依次强制跑：

1. `RBF + prescreening`
2. `GP + LCB`
3. `RBF + local search`
4. `GP + EI`
5. `PRS + prescreening`
6. `PRS + local search`
7. `KNN + L1-exploitation`
8. `KNN + L1-exploration`

这里有个要注意的小点：

- 论文正文里举例的 `CA` 顺序是从 `GP + LCB` 开始
- 代码里实际先跑的是 `RBF + prescreening`

但本质影响不大，因为目的只是：

- 让每个合法组合 arm 至少被试一次

#### 8.3.4 第 9 轮开始怎么选

第 9 轮以后，代码进入真正的两层 UCB 选择。

先看高层 model：

- `rbf_model`
- `gp_model`
- `prs_model`
- `knn_model`

这些数组存的不是“model 自己的独立奖励公式”，而是：

- 该模型下面所有低层 arm 历史奖励的集合

例如：

- `Save_rp` 记录 `RBF + prescreening` 的奖励历史
- `Save_rl` 记录 `RBF + local search` 的奖励历史
- `rbf_model` 则把这两类奖励都汇总进去

所以代码里高层值：

- `mean(rbf_model)`

本质上就是：

- RBF 相关低层 arm 的平均奖励

这正好对应论文中高层价值等于关联低层价值均值的结论。

#### 8.3.5 用“代码执行视角”串一次完整主流程

如果你不想被很多文件名绕晕，最好的方法就是直接按一次完整迭代来理解 `AutoSAEA.m`。

可以把它想成下面 10 步。

1. 先准备初始数据库  
   代码用 `lhsdesign` 在定义域里采 `100` 个点，逐个调用 `FUN` 做真实 FE，把结果存进 `hx` 和 `hf`。

2. 进入 `while NFEs < MaxFEs` 主循环  
   这里只要真实评估次数还没到 `1000`，算法就继续。

3. 取当前最好的 100 个真实样本作为 population  
   代码对 `hf` 排序，取最好的前 `gs=100` 个点得到 `ghx, ghf`。

4. 如果前 8 轮还没跑完，就按预设顺序把 8 个合法组合试一遍  
   这是为了避免一开始某些 arm 完全没有历史，UCB 无法稳定比较。

5. 如果已经过了前 8 轮，就开始真正的 TL-UCB  
   先比较 4 个高层 model 的 UCB 值，再在被选中的 model 下比较 2 个低层 arm 的 UCB 值。

6. 根据选中的组合 arm 产生一个 candidate  
   具体做法可能是：
   - 先生成一批 offspring 再筛一个
   - 或者直接在 surrogate 上做 local search

7. 对 candidate 做一次真实 FE  
   这一步最贵，也是整个循环里最珍贵的一步。

8. 把 candidate 加回数据库  
   代码把新点追加到 `hx`、把新 fitness 追加到 `hf`，同时更新 `CE` 和 `gfs`。

9. 更新低层奖励  
   调用 `Low_level_r.m`，根据 candidate 在当前 population 中的排名，得到本轮低层奖励。

10. 更新高层和低层的历史统计  
   代码把这个 reward 追加到相应的低层历史数组与高层历史数组，供下一轮 TL-UCB 使用。

所以代码的真正主骨架其实并不复杂：

`维护数据库 -> 取当前 best population -> 选 model -> 选 criterion -> 生成 candidate -> 做 1 次真实 FE -> 更新奖励统计 -> 进入下一轮`

你只要抓住这个主骨架，后面每个 arm 文件都只是“第 6 步如何产生 candidate”的不同实现。

## 9. `TL_UCB.m` 和奖励更新是怎么落地的

### 9.1 `TL_UCB.m`

`TL_UCB.m` 很短，核心就一句：

`U_value = q_value + sqrt((apha * log(id)) / length(sum_reward));`

这对应论文里的：

- 价值项 `Q`
- 探索项 `sqrt(alpha * ln(t) / T)`

其中：

- `id` 对应当前迭代号 `t`
- `length(sum_reward)` 对应该 arm 被选次数 `T`
- `q_value` 是这个 arm 的历史均值奖励

也就是说，代码没有显式维护一堆 `T_H`、`T_L` 计数器，而是直接用：

- 奖励数组的长度 = 被选次数

这是一种更朴素的实现，但和论文思想是一致的。

#### 9.1.1 `TL_UCB.m` 本身只是一个“单个 arm 打分器”

这里有一个很容易误解的点：

- `TL_UCB.m` 这个文件本身并没有完成“两层选择”
- 它只是根据传入的 `q_value`、`id` 和历史长度，返回一个 UCB 分数

也就是说：

- “两层”这件事不是在 `TL_UCB.m` 内部完成的
- 而是在 `AutoSAEA.m` 里通过调用两轮 `TL_UCB.m` 完成的

所以你可以把这两个文件分工理解成：

- `TL_UCB.m`：给一个 arm 算分
- `AutoSAEA.m`：决定先给哪些高层 arm 算分，再给哪些低层 arm 算分

#### 9.1.2 代码里是怎么完成“高层 TL-UCB”的

在 `AutoSAEA.m` 里，第 9 轮以后会先循环 4 个 model：

- `RBF`
- `GP`
- `PRS`
- `KNN`

对每个 model，代码都会做两件事：

1. 取它的历史奖励数组  
   例如 `rbf_model`、`gp_model`

2. 计算它当前的均值奖励  
   例如 `mean(rbf_model)`、`mean(gp_model)`

然后调用：

`TL_UCB(sum_reward, id, q_value, apha)`

得到这个 model 的 UCB 值，存入：

- `U_model_value(i)`

最后取 `U_model_value` 最大者作为高层选择结果。

这一步对应的正是论文公式 (22)。

#### 9.1.3 代码里是怎么完成“低层 TL-UCB”的

高层选中之后，代码不会再比较所有 8 个组合 arm，而是只比较该高层 arm 的两个子 arm。

例如如果高层选中了 `RBF`，代码只会比较：

- `Save_rp`
- `Save_rl`

也就是：

- `RBF + prescreening`
- `RBF + local search`

它们各自先算均值，再调用 `TL_UCB` 算 UCB 分数，最后取更大的那个。

这一步对应论文公式 (23)。

#### 9.1.4 为什么代码里不写 `T_a^H(t)` 和 `T_a^L(t)` 也能工作

论文伪代码里显式维护了：

- `T^H`
- `T^L`

代码里没有额外定义这些数组，是因为作者用了一个更省事的等价表示：

- 一个 arm 历史奖励数组的长度，就是它被选中的次数

例如：

- `length(Save_gl)` 就等于 `GP + LCB` 被选过多少次
- `length(gp_model)` 就等于 `GP` 相关历史记录累计了多少次

所以：

- 论文是“显式计数”
- 代码是“用数组长度隐式计数”

思想上并没有变。

### 9.2 `Low_level_r.m`

这份文件实现论文中的低层奖励公式。

逻辑是：

1. 把当前种群 fitness `ghf` 和新候选点 `candidate_fit` 拼起来
2. 排序
3. 找出新点排第几
4. 按照名次换算成 `[0,1]` 奖励

代码中的：

`reward = -1/N * in + (N+1)/N`

就是论文里的低层奖励。

如果新点刚好成为历史最优，代码还会打印一条日志：

- 当前最优是多少
- 是哪个 arm 得到的
- 当前 `NFE` 是多少

这有利于看运行过程。

#### 9.2.1 `Low_level_r.m` 的代码动作其实非常直接

这份函数可以拆成 4 个动作理解。

1. 取当前 population 的真实 fitness `ghf`
2. 把新点 `candidate_fit` 拼进去
3. 排序，看新点排第几
4. 用线性公式映射到 `[0,1]`

也就是说，`Low_level_r.m` 根本不关心：

- surrogate 是 GP 还是 RBF
- infill criterion 是 EI 还是 prescreening

它只关心一个问题：

> 你这一轮最终送去真实 FE 的那个点，在当前最优 100 个样本里能排到什么位置？

这正是 TL-R 低层奖励设计的核心。

#### 9.2.2 代码里为什么传入的是 `ghf` 而不是整个 `hf`

这也很值得注意。

代码计算奖励时用的是：

- 当前 population `ghf`

而不是：

- 整个历史数据库 `hf`

这和论文是对齐的，因为论文的低层奖励本来就是：

- 新点相对当前 population 的排名

不是：

- 相对所有历史点的全局排名

这样做的含义是：

- 奖励评价更加“当前态”
- 更关注本轮 candidate 对当前搜索状态是否有帮助

而不是把很早以前的历史点也一起混进去。

### 9.3 高层奖励在代码里没有单独写成一个函数

这一点非常值得单独说明。

论文里把高层奖励单独写成了：

- 低层值的变化量
- 再按关联低层 arm 数量归一化

而代码并没有再写一个独立的 `High_level_r.m`。

它采取的是更直接的做法：

1. 先计算这次低层 arm 的 reward
2. 把 reward 追加到对应低层历史数组，例如 `Save_gl`
3. 同时把 reward 也追加到所属模型总数组，例如 `gp_model`
4. 之后高层值直接用 `mean(gp_model)` 计算

这种写法虽然和论文公式形式不一样，但思想上是一致的：

- 高层值最终仍然反映该模型关联低层 arm 的整体表现

你可以把它理解为：

> 论文是“显式推导高层奖励如何传播”，代码是“直接维护传播后的结果”。

#### 9.3.1 代码里的 TL-R 更像“数组统计版”

如果严格对照论文，你会发现代码没有显式写出下面这些量：

- `Q_{a_t^L}^L(t+1) - Q_{a_t^L}^L(t)`
- `r_{a_t^H}`
- `Q_{a_t^H}^H(t+1) = Q_{a_t^H}^H(t) + r_{a_t^H}`

但代码依然实现了相近思想，因为它维护的是：

- 低层 reward 历史
- 高层 model 汇总 reward 历史

之后通过 `mean(...)` 取均值，作为下一轮 UCB 的 `Q`。

所以代码做的事可以概括成：

1. 先显式算低层 reward
2. 把 reward 存起来
3. 用 reward 历史均值作为下一轮价值估计

这是一种“更工程化、更易写”的实现。

#### 9.3.2 论文公式和代码实现之间的关系怎么理解

最稳妥的理解方式是：

- 论文给的是理论上更清楚的两层奖励传播推导
- 代码给的是便于 MATLAB 实现的统计式写法

也就是说：

- 如果你的目标是理解方法，优先看论文公式
- 如果你的目标是理解作者程序怎么跑，优先看代码里的 reward 数组维护

两者不是完全逐字符一样，但表达的是同一个核心思想：

> 低层根据 candidate 质量获得直接反馈，高层根据低层长期表现获得间接反馈。

#### 9.3.3 从代码角度看，TL-R 实际发生在什么地方

在主循环里，一旦某个 arm 运行结束，会返回一个 `reward_xx`。  
然后 `AutoSAEA.m` 立刻做两件事：

1. 把它追加到对应的低层数组  
   例如 `Save_gl = [Save_gl, reward_gl]`

2. 把它追加到对应 model 的总数组  
   例如 `gp_model = [gp_model; reward_gl]`

于是下一轮：

- `mean(Save_gl)` 代表低层 `GP + LCB` 的当前价值
- `mean(gp_model)` 代表高层 `GP` 的当前价值

从程序执行角度说，TL-R 就是这样被落地的。

## 10. 8 个 arm 在代码里分别怎么实现

下面按文件解释。

### 10.1 `GP_lcb_arm.m`

这份文件对应：

- `GP + LCB`

流程是：

1. 用当前种群 `ghx, ghf` 拟合 GP
2. 对 DE 生成的一批 `offspring` 做预测
3. 对每个 offspring 计算：
   - 预测均值
   - 预测 MSE
   - `LCB = mean - 2 * std`
4. 选 `LCB` 最小的那个点
5. 如果该点没在历史数据库里出现过，就做真实 FE
6. 更新 `hx/hf/gfs`
7. 用 `Low_level_r` 算奖励

这里 `w=2` 与论文一致。

### 10.2 `GP_ei_arm.m`

这份文件对应：

- `GP + EI`

流程和 `GP_lcb_arm.m` 类似，只是评分规则换成了 EI。

一个小细节是：

- 论文写的是“最大化 EI”
- 代码里写成了一个带负号的 EI，然后取最小值

本质上是等价的，只是为了和“最小化目标”的代码风格统一。

### 10.3 `RBF_pre_arm.m`

对应：

- `RBF + prescreening`

流程是：

1. 用当前种群训练 RBF surrogate
2. 对 DE 生成的一批 offspring 做预测
3. 选 surrogate 预测最小的那个
4. 做一次真实 FE
5. 计算低层奖励

它很直观，就是：

> 先粗筛一批候选，再送一个最有希望的去做真评估。

### 10.4 `RBF_ls_arm.m`

对应：

- `RBF + local search`

这里和 `RBF_pre_arm.m` 的关键区别是：

- 它不是只在一批现成 offspring 里挑
- 而是调用 `DE_optimizer` 在 surrogate 上直接搜索最优点

代码里：

- `flag = 1` 表示当前优化对象是 RBF surrogate
- `Max_NFE = 100 * D + 1000`

这和论文对 local search 的描述一致。

### 10.5 `PRS_pre_arm.m`

对应：

- `PRS + prescreening`

流程和 `RBF_pre_arm.m` 基本同型，只不过 surrogate 换成了 PRS。

代码里用：

- `srgtsPRSSetOptions`
- `srgtsPRSFit`
- `srgtsPRSEvaluate`

默认是二次响应面。

### 10.6 `PRS_ls_arm.m`

对应：

- `PRS + local search`

和 `RBF_ls_arm.m` 类似，只不过：

- `flag = 0`

表示 `DE_optimizer` 内部应当调用 PRS 的预测函数，而不是 RBF 的预测函数。

### 10.7 `KNN_eoi_arm.m`

对应：

- `KNN + L1-exploitation`

它的逻辑是：

1. 当前种群已经按 fitness 排好序
2. 按 `level=5` 分成 5 个等级
3. 最好的那一层是 `L1`
4. 用 `ClassificationKNN.fit` 训练 1-NN 分类器
5. 对 offspring 预测类别
6. 保留被预测成 `L1` 的候选点
7. 对这些候选点，计算它们到 `Parents_L1` 的距离
8. 选那个“离优秀点簇最靠近”的点

具体在代码里体现为：

- 对每个候选点，算它到所有 `Parents_L1` 的距离
- 再看“最大距离”有多大
- 选 `max_dist` 最小的

直觉就是：

> 这个点虽然是新点，但它整体上还待在优秀样本簇附近，所以更偏 exploitation。

### 10.8 `KNN_eor_arm.m`

对应：

- `KNN + L1-exploration`

前半段和 `KNN_eoi_arm.m` 一样，都是：

- 训练 KNN
- 找预测为 `L1` 的候选点

区别在后半段：

- 它看的是候选点到 `Parents_L1` 的“最近距离”
- 再选最近距离最大的那个

直觉就是：

> 这个点也像优质区域里的点，但它和已有优秀样本不挤在一起，所以更偏 exploration。

## 11. DE 在代码中扮演什么角色

### 11.1 `DEoperator.m`

这份文件负责：

- 生成一批 offspring

它的变异形式接近论文里的：

`x_i + F * (x_best - x_i) + F * (x_r1 - x_r2)`

含义是：

- 朝当前最好点靠近一点
- 再叠加两个随机点的差分方向

之后再做交叉、边界修复。

所以你可以把它理解成：

- `DEoperator.m` 是“候选点生成器”

它服务于：

- GP 的 LCB/EI
- RBF/PRS 的 prescreening
- KNN 的两种准则

### 11.2 `DE_optimizer.m`

这份文件不是对真实目标函数做 DE，而是：

- 对 surrogate 面做 DE

它主要服务于：

- `RBF + local search`
- `PRS + local search`

它的搜索边界不是整个原始搜索空间，而是：

- 当前种群 `ghx` 的逐维最小值到最大值

这与论文里 local search 的定义一致，是一个局部子空间搜索。

## 12. surrogate 相关代码怎么理解

### 12.1 RBF 部分

RBF 相关文件主要有：

- `my_rbfbuild.m`
- `my_rbfpredict.m`
- `srgtsRBFSetOptions.m`
- `srgtsRBFFit.m`

它们实现的是一个基于 cubic basis 的 RBF surrogate。

从 `RBF_pre_arm.m` 调用参数看，作者用的是：

- `RBF_type = 'CUB'`
- 并带多项式项

所以这部分和论文中的 RBF 建模描述是对得上的。

### 12.2 PRS 部分

PRS 相关代码在：

- `prs/`

其默认配置来自：

- `srgtsPRSSetOptions.m`

其中默认是：

- `PRS_Degree = 2`
- `PRS_Regression = 'Full'`

也就是说，代码中的 PRS 就是论文说的二次多项式响应面。

### 12.3 GP 部分

GP 相关主要有：

- `GP_fit.m`
- `predictor.m`

`predictor.m` 是 DACE 风格的 GP 预测器，可以给出：

- 预测值
- MSE

而 `GP_fit.m` 负责拟合超参数。

但这里也是整个代码里最需要小心的一块，因为它依赖一些**当前文件夹里看不到的外部函数**，这一点我会在后面的“依赖与复现注意事项”里单独说。

### 12.4 KNN 部分

KNN 部分比较直接：

- 使用 MATLAB 的 `ClassificationKNN.fit`
- 用当前种群排名构造类别标签
- 只取 `k=1` 的最近邻思路

它并不是在做复杂机器学习，更像是在做一个：

- “优秀区域判别器”

## 13. 论文和代码是一一对应的吗

总体上是对应的，但不是“逐行照搬伪代码”，而是“思想一致，代码实现更工程化”。

下面给一个对照表。

| 论文概念 | 代码位置 | 说明 |
| --- | --- | --- |
| 初始 LHS 采样 | `AutoSAEA.m` | 初始 100 个样本 |

| DE 生成 offspring | `DEoperator.m` | 供多种 arm 复用 |
| DE surrogate local search | `DE_optimizer.m` | 供 RBF/PRS local search 复用 |

## 14. 代码里有哪些实现细节值得特别注意

这一节不是在挑刺，而是告诉你：

> 静态阅读代码后，有哪些地方是“论文里没强调，但代码复现时必须注意”的。

### 14.1 高层奖励是“隐式实现”的

论文把高层奖励写成了公式 (26) 到 (30)。  
代码没有专门再写一次这个公式，而是直接通过：

- 低层奖励历史数组
- 模型汇总奖励数组

来实现同样效果。

所以如果你以后想自己重写 Python 版，不要机械照着代码里的数组堆叠写法搬；更应该先理解论文里的高层价值推导。

### 14.2 代码显式处理了重复点

在 8 个 arm 文件里几乎都能看到：

- 先检查 `candidate_position` 是否已经在 `hx` 里出现过

如果出现过：

- 就不给真实 FE
- 奖励记为 0

这是一种很实用的工程处理，因为 FE 很贵，没必要重复评估相同点。

### 14.3 代码里高层 arm 的顺序和论文正文顺序不完全一样

论文正文里常写：

- GP
- RBF
- PRS
- KNN

代码里高层 UCB 的实现顺序是：

- RBF
- GP
- PRS
- KNN

前 8 次冷启动顺序也与论文示例的 `CA` 次序不同。  
但只要每个合法组合都被尝试过一次，这个差异通常不影响方法本质。

### 14.4 `run_myexperiment.m` 只覆盖了 benchmark 主实验

你能直接看到：

- CEC2005
- CEC2015

但论文里还讲了：

- adaptive behavior analysis
- oil reservoir production optimization

这些部分在作者公开的这个目录里**并没有完整的专门实验脚本**。

换句话说：

- 代码足够说明核心算法
- 但不等于论文所有实验都在这个文件夹里完整可一键复现

### 14.5 代码里有一些文件名/函数名和依赖上的风险点

这一点很重要，我单独列出来。

#### 1. `DEoperator.m` 的主函数名写成了 `DEoperating`

文件名是：

- `DEoperator.m`

但文件里第一行函数定义是：

- `function [U] = DEoperating(...)`

而调用处写的是：

- `DEoperator(...)`

从静态阅读看，这是一个需要注意的地方。

#### 2. `GP_fit.m` 的主函数名写成了 `dacefit_3`

文件名是：

- `GP_fit.m`

但函数定义是：

- `function [dmodel, perf] = dacefit_3(...)`

而 `GP_lcb_arm.m` 里调用的是：

- `GP_fit(...)`

`GP_ei_arm.m` 里调用的是：

- `dacefit_3(...)`

这说明 GP 部分的命名存在明显不统一。

#### 3. GP 依赖若干当前文件夹中未见到的外部函数

静态搜索后，这个文件夹里没有找到以下实现：

## 15. 结合代码再说一遍 AutoSAEA 的“本质”

从代码看，AutoSAEA 的本质可以浓缩成下面这句话：

> 它维护一份“当前最好的 100 个真实评估样本”，然后每轮只花 1 次真实 FE，去测试“当前最值得尝试的 surrogate model + infill criterion 组合”是否真的能给出一个高排名新点。

注意这个描述里有 3 个非常关键的点。

### 15.1 它是在线方法选择，不是离线训练一个固定策略

它不会先在很多问题上离线训练一个大模型，然后测试时直接输出“应该选 GP”。  
它是在每次优化过程中：

- 边搜索
- 边收集反馈
- 边调整方法偏好

### 15.2 它的反馈非常轻量

它不需要复杂神经网络训练，也不需要长时序 credit assignment。  
它只需要：

- 新点的排名

就能更新 bandit。

这也是它相对容易解释、容易实现的原因。

### 15.3 它真正学的是“哪个组合最近更靠谱”

它不是在学 surrogate 的参数本身，surrogate 每轮都重新拟合。  
它在学的是：

- 哪个 model family 最近对当前问题更合适
- 在这个 model family 下，哪个 infill criterion 最近更合适

所以它学的是：

- **方法偏好**

而不是：

- **目标函数本身**

## 16. 如果你把论文和代码一起看，最容易混淆的地方

### 16.1 surrogate model 不是最终决策器

第一次读这种论文时，很容易把重点全放到 GP/RBF/PRS/KNN 上。  
但实际上，作者真正的主角不是某个 model，而是：

- model 和 infill criterion 的联合选择机制

所以你不应该把论文理解成：

- “这是四模型集成”

更准确的理解是：

- “这是一个两层在线方法选择框架，底下挂着四类 surrogate family 和八个合法组合 arm”

### 16.2 奖励不是“谁找到全局最优就给 1”

论文的低层奖励是：

- 当前 population 排名奖励

这是一种很重要的设计取舍。

它意味着：

- 只要一个 arm 持续给出高质量候选点，它就能稳定拿到不错的奖励

而不是必须：

- 每次都直接刷新全局最优

这让 bandit 的反馈更平滑。

### 16.3 KNN 不是在预测精确函数值

KNN 这里只做分类：

- 谁像优秀层
- 谁不像优秀层

所以 KNN arm 的目标不是“预测最准”，而是：

- 帮忙把候选点往可能的优质区域聚焦

### 16.4 local search 不是对真实函数做局部优化

它优化的是 surrogate，不是真实昂贵函数。  
最后只把 surrogate 认为最好的那个点拿去做一次真实 FE。

所以 local search 本质上仍然是在：

- 省真实 FE

## 18. 如果你只想记住最关键的内容

我建议你记住下面 10 句话。

1. `AutoSAEA` 解决的是昂贵优化，不是普通大规模便宜优化。
2. `SAEA` 的核心是“少做真实 FE，多做便宜 surrogate 预测”。
3. surrogate model 决定“如何近似目标函数”。
4. infill criterion 决定“下一次真实 FE 评估谁”。
5. 论文认为 model 和 infill criterion 是强耦合的，应该联合选择。
6. AutoSAEA 用两层老虎机来做这个联合选择。
7. 第一层选 surrogate model，第二层选该模型下的 infill criterion。
8. 低层奖励看的是“新点在当前 population 里的排名”。
9. 高层价值本质上来自其关联低层 arm 表现的平均。
10. 代码总体忠实实现了论文核心思想，但包含外部依赖、命名不统一和平台相关问题。

## 19. 最后给你一个最通俗的比喻

你可以把 AutoSAEA 想成一个“很会省钱的试验主管”。

他手下有 4 类顾问：

- GP 顾问
- RBF 顾问
- PRS 顾问
- KNN 顾问

每类顾问下面又有 2 种做事风格：

- 保守一点
- 激进一点

每次真正做实验都很贵，所以主管不会让所有顾问都全面展开，只会：

1. 先挑一个当前最值得信的顾问
2. 再挑这个顾问当前最值得信的一种做事风格
3. 只做 1 次真实实验
4. 看这次结果好不好
5. 再调整下次更相信谁

这就是 AutoSAEA。

它最有价值的地方，不是某个公式本身，而是这个思路：

> 在昂贵优化里，不仅要优化解，还要在线优化“当前该用哪种搜索策略”。
