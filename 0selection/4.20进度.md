## 一、项目背景与核心目标

### 1.1 项目一句话概括

训练**一个**神经网络（unified selector，统一选择器），在 **18 个路径规划问题（routing problem）**上，为每个测试实例**从多个候选求解器（solver / arm，每个候选解法叫一个"arm/臂"）里挑出最便宜的那个**。

- **selector = 选择器**：我们要训练的神经网络
- **arm = solver = 候选求解器**：已有的一个启发式/神经求解算法，比如 `LEHD`、`MTPOMO`、`GLOP`
- **top1 准确率** = selector 挑中的 arm 与 oracle（上帝视角挑的最佳 arm）一致的比例
- **SBS（Single Best Solver）= 单一最强求解器**：在 val 上表现最好的那个 arm，作为 baseline（基线）
- **oracle** = 上帝视角，假设每个实例都能挑到最便宜的 arm，是准确率的上界

### 1.2 为什么这个问题值得做

- 不同 routing 问题有不同的最佳求解器；同一个问题的不同规模、不同分布也会让最佳求解器变化。
- 已有 18 个现成的求解器，**挑错一个成本差距可以高达几十个百分点**。
- 如果能用**一个**selector 在所有 18 个问题上保持高 top1，相当于一个通用的"调度路由器"——这是用户最在意的效果目标。

### 1.3 用户核心关切（再次强调）

> **我现在面临的问题仍然是两个**
> 1. **top1 率太低**，我期望能够达到 80% 以上。
> 2. **很多方法不会被选择**，出现了"坍缩现象"（support collapse）。
>
> **我的关注点仍然是"效果"，而不是创新。**

## 二、数据集与评测协议

### 2.1 数据集规模

| 问题类 | 问题数 | train / val / test（每问题） | arm 数 K_p |
|---|---:|---:|---:|
| TSP | 1 | 10000 / 1000 / 1000 | 10 |
| CVRP | 1 | 10000 / 1000 / 1000 | 9 |
| ATSP | 1 | 10000 / 1000 / 1000 | 3 |
| MVRP（15 个变体） | 15 | 10000 / 1000 / 1000 | 4（统一） |
| **总计** | **18** | **180000 / 18000 / 18000** | K_p ∈ {3, 4, 9, 10} |

- **MVRP（Multi-constraint VRP）**：是 VRP 的扩展，通过在基础 CVRP 上叠加若干约束生成 15 个子问题：`O`（开放路径）、`B`（回程）、`L`（距离限制）、`TW`（时间窗）。例如 `OVRPBLTW` = 同时有开放路径、回程、距离限制、时间窗。
- 每个实例特征 = 节点坐标（TSP/CVRP/MVRP）或距离矩阵（ATSP），加上可选的约束位向量。

### 2.2 arm 池结构

- **M_GLOBAL = 18 个全局唯一求解器**（名字去重后的并集）。
- **总 (problem, arm) 对数 = 82**（这是 selector 实际要区分的"arm"总数）。
- 具体对应：
  - TSP: `DACT, DIFUSCO, ELG, GLOP, INVIT, LEHD, LIH, OMNI, T2T, UDC`（10 个）
  - CVRP: `DACT, ELG, GLOP, ICAM, INVIT, LEHD, OMNI, RELD_CVRP, UDC`（9 个）
  - ATSP: `GLOP, MATNET, MATPOENET`（3 个）
  - 15 个 MVRP 变体共享 `MTPOMO, MVMOE, RELD_MOEL, RELD_MTL`（每个 4 个 → 60 个 arm）
  - **合计 = 10 + 9 + 3 + 60 = 82**

### 2.3 评测指标

- **strict top1**（严格 top1）：selector 挑出的 arm 与 oracle 的 arm 一致，才算对。macro 平均（18 个问题各自准确率求平均）。**这是我们主要追的指标。**
- **macro_vs_sbs_pct**：所选 arm 的 mean cost 相对 SBS 的百分比差距。负数代表击败 SBS，正数代表被 SBS 击败。
- **relative regret %**（相对后悔值）：`(selected_cost - oracle_cost) / |oracle_cost| × 100%`。这是比 top1 更"柔和"的指标，因为 top1 错选不一定差很多。
- **bootstrap 95% CI**（配对分层自助置信区间）：每次按 problem 分层重采样 18000 个实例，计算 10000 次，给出 top1 差距的 95% 置信区间。跨零就是不显著（not significant）。

### 2.4 Pre-registered 协议（验证集锁定）

为避免"在测试集上调参然后报告 test 好"的作弊嫌疑，每个正式报告的方法都要：

1. 在 val 上扫描超参；
2. 按事先声明的准则（比如 val 上 top1 最大）**锁定唯一一组超参**；
3. 用这组超参**一次性**评估 test；
4. 用配对 bootstrap 判断显著性。

这是我们 R36–R38 的主要评测模式。**凡是没走过这个协议的数字都标注为"exploratory（探索性）"**，不能作为结论。

## 三、当前基线模型（R18_alltail）

### 3.1 架构

- **坐标编码器（CoordEncoder）**：4 层 Transformer encoder（Transformer 编码器），d=128，4 头，GELU，masked mean-pool。用来编码 TSP/CVRP/MVRP 的节点坐标。
- **矩阵编码器（MatrixEncoder）**：ATSP 用不了坐标，改用 10 维手工统计特征（均值、方差、对称度、三角不等式违反率等）的 MLP。
- **头 MLP**：拼接 `[实例表征 g, 问题 ID 嵌入 E_prob, 约束位向量 cbits, 坐标尺度归一]` → 融合成 h_b，然后每个 arm 的 pair-feature `[h_b, e_solver, h_b*e_solver, |h_b - e_solver|]` → MLP → per-arm logit。
- **FiLM（Feature-wise Linear Modulation，特征级线性调制）**：问题 embedding 作为 gain/bias 调制 encoder 输出。
- **problem_solver_bias**：(P × M_GLOBAL) 的可学习偏置矩阵，专门捕捉"某某问题上某某 solver 通常更好"的先验。
- **masked softmax**：对不在 pool 里的 arm 加 -∞，只在 K_p 个可用 arm 之间做 softmax。

### 3.2 训练流程（Self-distillation 管线）

`R18_alltail` 是一条长链条的终点：

```
S1-seed0 (scratch, CE on soft label)  →
S2 (problem dropout + PL 辅助损失)  →
S3 (FiLM + ensemble teacher distillation)  →
S4 (专家蒸馏 distill from specialists)  →
S5 (tail 继续训练 + TCVA)  →
R18_alltail (S5 基础上再 tail 一次 cosine 到 1e-5)
```

- 训练 loss：`listwise CE` 对 regret-soft label（把 oracle 的 one-hot 换成按 regret 加权的分布），加 `combined_cost_loss` 尝试过但总体变差（见 Round 2 反馈）。
- **R18 超参**：d=128，depth=4，lr=1e-5（cosine），warmup 500，tau=0.02，3 epochs tail。

### 4.2 Fresh loop（2026-04-18 至 2026-04-20）：后处理、诊断、证伪

全部以 R18_alltail 为 base，各种后处理方法都是**不改 base 权重**，只在推理阶段叠加修正。

#### 4.2.1 k-NN 检索先验（retrieval prior）

**思想**：用 R18 的 pooled 实例表征 g ∈ R^128 做近邻检索，在 train set 里找最相似的 k 个实例，用它们的 oracle 分布作为"先验"。

- **oracle-vote prior（邻居投票先验）**：k=32 个邻居，按余弦相似度 softmax 加权（τ=0.1），累加到每个 arm 上，得到每个 arm 的"邻居投票"概率分布。
- **cost-rank prior（代价排序先验）**：不用邻居 oracle 的 one-hot，而是用邻居的"arm cost 排序" 按 softmax 加权平均 → 每个 arm 得到一个平均 rank，低 rank 代表在邻居里便宜。
- **gated blend（门控融合）**：final_logit = α · base_norm + (1−α) · log(prior)，且**只在 base 的 top1-top2 margin 小于 δ 时才应用**（低置信度才介入，否则信 base）。

## 五、核心诊断结论：为什么所有后处理都不 work

### 5.1 支持塌陷（support collapse）

> 82 个 arm 里，**50 个从未被 R18 作为 top1 选过**。其中 35 个是"真塌陷"（对应 oracle 质量不小但 base 系统性忽略），15 个是"良性退化"（几乎没有 oracle 质量）。

- **zp mass**（zero-pick mass，塌陷 arm 上的 oracle 质量）= **20.01%**（3601/18000）
- 意味着 **1/5 的 test 实例 base 从定义上不可能做对**——它的 oracle arm 在 R18 的支持集之外
- 各问题 zp mass 差距极大（见 `R29b_zp_rescue` per-problem 表）：
  - **最严重**：VRPL 54.6%，VRPBTW 51.2%，OVRPL 50.6%，VRPBLTW 49.0%，VRPBL 46.3%
  - **比较轻**：ATSP 2.4%，OVRPBL 2.6%，OVRPB 3.4%，OVRPLTW 7.8%
- 说明 **R18 base 在多约束 MVRP 上塌缩得非常严重**。基本上 base 对这些问题只会选其中 1-2 个 solver，而真正便宜的 solver 经常在支持集外。

### 5.2 R39 gross rescue / gross harm 分解（central figure）

把 18000 个 test 实例按 oracle arm 是否在 val-定义的塌陷集里分两块：
- **on-collapse（塌陷子集）**：N = 4714，base **必错**（因为 base 的 top1 永远不在这个 arm 集）
- **off-collapse（非塌陷子集）**：N = 13286，base 本来就能做对不少

对每种后处理方法，分别统计：
- **rescue**：base 错、方法对（新增正确数）
- **harm**：base 对、方法错（新增错误数）
- **net** = rescue − harm

结果表（R39 原始输出）：

| 方法 | zp-rescue | zp-harm | Δzp | non-zp-rescue | non-zp-harm | Δnon-zp | **总 net** |
|---|---:|---:|---:|---:|---:|---:|---:|
| gated α=0.4, δ=0.08（test-cherry） | +596 (12.6%) | **0** | +596 | +984 (7.4%) | 1478 (11.1%) | **−494** | **+102 (+0.57%)** |
| gated α=0.5, δ=0.10（robust） | +682 (14.5%) | **0** | +682 | +1016 (7.6%) | 1629 (12.3%) | **−613** | **+69 (+0.38%)** |
| gated α=0.8, δ=0.2（val-best） | +438 (9.3%) | **0** | +438 | +815 (6.1%) | 1236 (9.3%) | **−421** | +17 (+0.09%) |
| prior-only α=0.5 | +797 (16.9%) | **0** | +797 | +1142 (8.6%) | 1902 (14.3%) | **−760** | +37 (+0.21%) |

**解读**：
1. **塌陷子集 harm 恒为 0**（base 本来就 0 对，怎么动都不会变差），rescue 稳定为正 → 机制是真的。
2. **非塌陷子集 harm > rescue**（约 `harm/rescue ≈ 1.2–1.7`），每个尝试都被抵消 80–95%。
3. **总 net 被 bootstrap 噪声上限（±108 = ±0.006 top1）淹没**，所以统计上不显著。
4. 结论：**任何对 base 全局的后处理矫正，在"救塌陷 arm"的同时不可避免地会"搞坏非塌陷 arm"**——因为修改的信号是同一个（检索先验），没有办法只挑塌陷样本改而不伤别人。

### 5.3 用户两个痛点对应的结论

| 用户的关切 | 诊断结论 |
|---|---|
| **top1 率太低** | R18 = 0.5193 是个硬墙；bucket 分解显示 77% regret 集中在 29% 的 >1% gap 硬样本上；**想过 0.60 很可能要换 base，不能靠后处理** |
| **很多方法不会被选择（坍缩）** | 确认：50/82 arm 零选、20% 质量被塌在 support 外；检索先验能局部救（8–17%），但全局救不动 |

## 六、**仍未充分尝试或值得重做的方向（给 reviewer 重点看）**

诊断 paper 框架虽然被 oracle-pro 给 8.5/10，但**用户要的是效果，不是诊断**。按照"诊断 → 改方案"的逻辑，以下方向 **reviewer 可以重点评估该不该做**：

### 6.1 ⭐ Plan B：深度换 encoder（**用户明确要求但还没跑**）

> 用户 4/19 初始指令原文：**"B: Deep encoder overhaul — Hierarchical GAT + ReZero + MBM three-way ATSP + CoE constraint-expert FFN."**

**现状**：**这个方案目前没有实际训练**。oracle-pro R1 的判断是"改 encoder 不太可能把 top1 拉到 0.8"，因此我把重心放在后处理上。但**既然所有后处理都失败了，这个坑必须回填**。

**计划**：
- **Hierarchical GAT（层次化图注意力网络）**：两层 graph attention，先邻接节点内 attend，再 cluster-level attend。对大规模 routing 尤其能扩展。
- **ReZero**（重置跳接）：每个残差块前乘一个可学习标量 α_block，初值 0，让训练更稳。
- **MBM three-way ATSP**（Matrix-Based MatNet 三路矩阵）：对 ATSP 做矩阵行/列/行列三路编码，比当前 10 维手工特征强得多（ATSP 当前 top1 几乎就是 SBS fallback）。
- **CoE FFN（Constraint-expert FFN）**：constraint 位对应的 expert MLP，mixture-of-experts 结构按 cbits 路由。
- **规模**：把 d 从 128 提到 256 或 384，depth 从 4 提到 8-12，参数量从 ~3M 涨到 ~20M。

**风险**：oracle-pro 认为只会带来 +1~+3 点 top1（从 0.52 到 0.53~0.55），离 0.8 还很远。但**至少应该跑完消融实验**再下结论。

### 6.2 ⭐ Plan C：二阶段 top-k 重排器（曾经失败过，需要换姿势重做）

> 用户原话：**"C: 对 top-2/top-3 进行第二阶段重排序，保留 S5 作为第一阶段；在具有零-pick 但 oracle 胜出的臂上进行难例挖掘。"**

**现状**：R12/R14 时代试过一版（R12_rerank_r12s1），失败——reranker 学到 α=1.0（纯 base）总是最好，因为：
1. Reranker 只在 "oracle-not-top-1" 的样本上训，没有 easy-case calibration（校准）
2. Reranker 的输入缺少跟 base 互补的信号

**改进方向**：
- 让 reranker 看到 base_logit + 检索先验 + per-arm learned embedding + problem embedding → 给 top-3 候选重新打分
- 训练数据**同时包含 easy（base 已对）和 hard（base 错、oracle 是 top-2/top-3）** 两类，按 oracle 位置的期望 reward 加权
- 难例挖掘（hard-negative mining）：优先采样 "oracle 是 base 的 top-2 或 top-3" 的实例
- 在 zp mass 上可能尤其有效——R29b 显示 prior-only 能把 zp top1 从 0 提到 12.7%，如果 reranker 能选出先验的建议 + base 的综合分最高者就可能正向

### 6.3 ⭐⭐ 训练时防塌陷（目前只尝试过 problem_solver_bias）

**这是最可能把 top1 从 0.52 提到 0.60+ 的方向，我还没系统性探索。**

- **class-balanced sampling**（类平衡采样）：按 oracle arm 的频率反比采样。当前 50/82 个 arm 从不被选，部分原因是这些 arm 在 train set 的 oracle 频率极低。
- **focal loss on collapsed arms**：对 oracle 在塌陷 arm 上的样本给更大的 loss 权重（γ=2 或 γ=5 的 focal）。
- **label smoothing across pool**：现在用的是 regret-soft label（按 regret 给 soft weight），但 top1 其实还是 sharp 的；换成 entropy-regularized label 可能鼓励 selector 保留对弱 arm 的概率。
- **CQR-style distribution regularizer**：加一项损失 `−H(p)` 惩罚过度集中的选择分布，迫使 selector 对候选 arm 保持非零概率。
- **oversample on zp oracle instances**：直接把"oracle 在 R18 never-pick arm 上"的 3601 个 train 实例的权重 ×3~×5。
- **arm-balanced mini-batch**：每个 minibatch 保证各 arm 作为 oracle 出现次数接近平衡。
- **arm-level auxiliary head**：给每个 arm 加一个"这个 arm 在这个实例上会不会 work"的二分类辅助头，正则化 arm 表征。

### 6.4 ⭐ 模型 scaling（规模放大）

当前 R18 只有 ~3M 参数，d=128，depth=4。对比：
- 同类 routing selector 文献里 MatNet、POMO、RELD 级别都是 10-50M。
- 用户允许用两张 3090（48GB 显存），当前一张的利用率 ~20% 还没吃满。

**建议系统性扫描**：
- d ∈ {128, 256, 384, 512}
- depth ∈ {4, 6, 8, 12}
- per-arm embedding dim ∈ {32, 64, 128}
- 训练轮数 ∈ {R18 当前 3 epoch tail, 10 epoch tail, 从 S5 重新 30 epoch}

### 6.5 可以尝试的其它方向

| 方向 | 假设 | 快速验证方法 |
|---|---|---|
| **双 GPU 并行** 把训练吞吐翻倍 | 当前 GPU 利用率 20%，瓶颈在数据加载 | 用 `nn.DataParallel` 或 `DistributedDataParallel`，再多线程 dataloader |
| **更多 teacher 蒸馏源** | S4 只蒸馏了 specialists；可以加 ensemble of diverse selectors 作为更强 teacher | 训一组 5 个不同 seed 的 specialists，mean-soft-target 作为 teacher |
| **Retrieval-augmented training** | 把检索先验当 feature 直接塞进 base 训练 | 每个 train instance 从另一 fold 检索，append 到 input，训练 base 看 R18 能不能借助检索学得更准 |
| **Self-consistency ensembling** | 不同 seed / TTA 的 top1 可能互补 | 5-seed majority vote（不是 logit avg），看能不能把 top1 拉过 0.55 |
| **Curriculum training**（课程学习） | 先在 easy (高 margin) 样本上预训练，再渐进加硬样本 | 按 oracle 的 top1 margin 分桶，从 easy 桶开始训 |
| **Per-arm learnable prompt** | 让 selector 按"要评估 arm X"生成 query，每个 arm 跟实例做 cross-attention | 类似 Perceiver 的 query-bottleneck 结构 |
| **Active learning on hard subset** | 用 bootstrap CI 找"当前 selector 不确定"的 train 实例，手动标 oracle（或 MC rollout） | 需要 simulator 接入 |

### 6.6 数据层面改进

- **更多 train 数据**：当前 18 × 10000 = 180k 实例，增加到 500k 以上。
- **更广的分布**：TSP/CVRP 当前规模 50-499，可以加 1000+ 实例。
- **真实 benchmark 混入 train**：TSPLIB / CVRPLIB 当前只在测试用，加入小部分到 train 可能让 selector 见到更真的分布。
