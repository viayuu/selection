# R32e / R33a 未明显提升的原因诊断

日期：2026-09-30。重点是 top1、mean cost 和训练有效性，不将选择分布作为主要诊断目标。

## 结论先行

**不能根据这两次 30 轮实验得出“方法特征无效”或“双流结构无效”。但证据也不支持“只要把同一配方多跑一些 epoch，就会明显提高”。**

目前最有依据的判断是：

1. 两次训练未建立完整的收敛判据，而且增大 batch 后没有补足优化器更新次数。
2. 两版模型在完整训练集上的 top1 也只有约 47%，并非训练集很好、验证集很差的典型严重过拟合。
3. 静态方法特征与自由 ID embedding 相加，对已知的固定方法池主要提供共享先验；本次模型在推理中对这条分支的依赖很弱。
4. 当前损失重点、尺度与“精确区分第一名，同时降低 cost”并不完全一致。有可测的失衡，而不只是权重名称的问题。
5. 多问题 batch 没有混错，但共享参数在单任务梯度间轮转，且 MVRP 占 15/18 的更新；负迁移值得单独验证，尚不能直接定罪。
6. 有一处真实的数据输入语义问题：`coord_dist` 是按实例索引猜测的桶，不是经过验证的真实坐标分布标签。

本次没有修改生产模型、训练目标或原数据，没有覆盖任何 checkpoint。新增的是诊断脚本、图和报告。另做了训练集小样本拟合探针，副本权重只存在内存中，未作为正式模型保存。

## 1. 本次实际检查了什么

- R32d / R32e / R33a 全部 30 个 epoch 的已有验证结果和训练日志。
- R32e / R33a 的 `best.pt`、`last.pt`，各自完整 180,000 个 train 样本与 18,000 个 val 样本重新推理，关闭 dropout，不更新权重。
- 验证集的去特征、打乱实例对应关系、类别权重校正探针；未用 test 调参。
- 每个问题抽 3 个固定训练 batch，每批 32 个实例，测共享实例 self-attention 编码器的梯度方向与损失分量梯度范数。
- R33a 在 TSP / CVRP / VRPTW 各 64 个固定训练实例上的纯 CE 拟合能力。
- 独立只读审计：全部 54 个 split、216,000 个实例、384 个方法结果文件，共 1,536,000 个 cost 的列对应和有限性。

主要机器可读结果：`summary_numbers.json`、`checkpoint_metrics.json`、`inference_probes.json`、`label_statistics.json`、`gradient_loss_components.json`。独立审计的具体结果见第 7 节。

## 2. 30 轮是否够：当前不能按“loss 看着平了”判断

之前实际执行的是 `for epoch in range(..., args.epochs)`。没有 early stopping，没有 warmup，没有学习率衰减；AdamW 的 lr 始终是 `2e-4`。因此之前的“跑完”只表示达到人为设定的 30 轮，不等于已证实充分收敛。

已有训练日志中的 loss 是**当前 epoch 起点到本次打印之间的累计均值**，不是最近 50 步均值；epoch 结束也不一定正好打印一次。历史图按每轮最后一次打印恢复，已明确标注，不伪装为精确 epoch-end loss。过去未记录逐轮 val CE、train eval top1，所以无法事后恢复这些完整曲线。

| 实验 | batch | 每问题每轮 batch 数 | 每轮 step 调用数 | 30 轮 step 调用数 | 验证集选中的 epoch，1 起算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| R32d，无方法特征基线 | 448 | 22 | 396 | 11,880 | 30 |
| R32e，加入方法特征 | 640 | 15 | 270 | 8,100 | 25 |
| R33a，双流联合编码 | 640 | 15 | 270 | 8,100 | 23 |

增大 batch 使计划更新次数减少 **31.82%**。在 batch=640 下约需 **44 轮**才能匹配原来的 11,880 次调用。这并不保证相同优化轨迹，但 30 对 30 不是等更新预算的比较。AMP 是否跳过个别 step 历史未记录，表中是调用次数，不承诺全部为成功参数更新。

R32e 最后 5 轮平均 val top1 为 46.2922%，前 5 轮为 46.3944%；R33a 分别为 45.8233%、45.9267%。两者尾部均有波动、没有稳定上升，说明应该测试降低学习率后的继续优化，而不是预言同 lr 长训必然有效。

本地 NSS 的 `config_TSP.yml` / `config_CVRP.yml` 是 50 轮、batch=64。在 10,000 个训练实例且不丢尾批的情况下，每个单问题约 7,850 次更新；当前每问题只有 450 次直接更新，尽管共享网络总共获得 8,100 次跨问题更新。两者任务、模型、目标不同，不能机械照抄轮数，但这说明单看 epoch 很容易误判训练预算。

应该同时观察：同口径 train/val CE、train/val top1、val mean cost / vs-SBS、逐问题指标、学习率、成功更新数及梯度范数。验证指标进入平台后降低学习率，再使用 patience；不要求训练 loss 完全不下降才停止，也不能因为训练 loss 下降就无限训练。早停基于泛化指标而非训练 loss 本身，参见 [Prechelt](https://page.mi.fu-berlin.de/prechelt/Biblio/stop_tricks1997.pdf)。大 batch 与更新预算的关系参见 [Hoffer 等](https://arxiv.org/abs/1705.08741)，不是对本项目结果的因果证明。

## 3. 重新测量：不是明显的全局严重过拟合

下表为本次完整 split、eval 模式复测；CE 不使用 class weight，方便 train/val 同口径比较。

| 模型 | Train top1 | Val top1 | Train CE | Val CE |
| --- | ---: | ---: | ---: | ---: |
| R32e best | 47.3289% | 46.8000% | 1.13055 | 1.14122 |
| R32e last | 47.2383% | 46.5333% | 1.13305 | 1.15032 |
| R33a best | 47.0883% | 46.8444% | 1.13851 | 1.14941 |
| R33a last | 47.1667% | 46.2833% | 1.14605 | 1.16067 |

训练与验证差距很小，说明主要现象是**连训练分布上的精确选择也没有充分学好**。这与欠拟合、优化受限、目标失配或特征不足相容，不能仅凭小差距把其中某一个解释认定为唯一原因。少数问题存在较大差距，例如 R32e TSP 为 38.17% / 35.00%，仍需要逐问题看。

口径注意：本次诊断用 FP32 costs 的 `argmin`，与 CE 训练标签一致；历史 eval 使用 GPU `argsort`。并列 cost 的 tie breaking、推理 batch 从 640 改为 160 的数值路径，会导致极少量边界样本差异。以上不替换历史正式结果，原始 json 保留。

小样本拟合探针：从 R33a best 加载副本，关闭 dropout，仅使用普通 CE，lr=2e-4、无 weight decay，每次固定 64 个 train 实例。

| 问题 | 初始 top1 | 50 次单问题更新后 top1 |
| --- | ---: | ---: |
| TSP | 43.75% | 100% |
| CVRP | 28.125% | 100% |
| VRPTW | 51.5625% | 100% |

这排除了这些样本上“完全无法反传或网络无法拟合”的解释；**不证明完整训练集可轻易记住，不证明泛化可达 80%，也不能单独证明多任务负迁移。** 探针同时改变了采样、dropout 和损失，只是容量/连通性检查，不是独立因素消融。

## 4. 方法特征为什么没有明显收益

表本身按用户提供的固定 34 维接入，ID 顺序与池一致。问题更可能在它的功能定位与使用强度。

固定方法池中，`e_s = ID_s + lambda * MLP(f_s)` 对每个 solver 都是一个静态向量。在确定性推理下，这个和值可以由另一套自由 ID embedding 表达。因此它没有扩充静态方法表示的可表达集合；它改变了参数化和共享先验，而不是凭空提供新的实例级胜负证据。结构类别相同的不同推理预算，例如 DIFUSCO/DIFUSCO500，仍完全依赖各自 ID 区分。

| 推理诊断，Val | R32e top1 | R33a top1 |
| --- | ---: | ---: |
| 正常输入 | 46.8000% | 46.8444% |
| 仅移除静态方法特征分支，保留 ID | 46.7667% | 46.8611% |
| 打乱同问题实例与预测的对应关系 | 34.2111% | 34.4722% |
| 只按 train 的 winner 频率排序 | 40.1111% | 40.1111% |

方法特征消融几乎不动，但实例打乱后明显下降：**模型确实学到了实例信号，不是只背方法先验；新增元信息的边际作用却很弱。** 去特征是 inference intervention，不等价于训练一个无特征模型，不能据此彻底否定这些字段。

向量范数也支持这个观察：R32e 加权特征 / ID 平均范数为 3.394 / 11.410；R33a 为 1.595 / 11.273。R33a 即使 lambda=1，因它的特征 MLP 输出不再单独 LayerNorm，实际幅度仍小。范数不是贡献的严格度量，但不能只比较 lambda=0.3 与 1.0 就认为后者特征更强。

不建议下一步继续凭直觉扩大元信息维度。先做相同训练预算和损失下的有/无特征对照；需要增强方法先验时，再考虑训练集构建的 performance profile 或可靠的推理预算字段，不能让 val/test cost 成为输入。

## 5. Q/KV、编码结构与损失

### Q/KV 不是目前被证明的主要错误

R33a 的每个 joint layer 已经同时包含 `Q=solver, K/V=node` 和 `Q=node, K/V=solver`，两个方向读取更新前状态。最后的 decoder 则是 `Q=pooled instance, K/V=updated solver`，每个 `S_j` 还直接进入共享打分头。因此它并没有缺少“solver 阅读实例”的通路，最后 decoder 的查询方向不能解释全部结果。

节点编码原本就是 4 层 self-attention，不是全 MLP。当前 encoder 是自定义带距离偏置的 Transformer，不是完整 NSS hierarchical encoder；联合编码没有 MatNet 外部 D，不能把 MatNet 的效果直接外推过来。

R33a 对比 R32e 同时移除了 problem/arm solver memory、set scorer、support 主分支及旧辅助头，并改变 feature MLP/权重。因此这是一组完整方法比较，不是只改 cross-attention 的干净消融。下一步如验证联合编码，应固定其他路径，比较无 joint / 单向 solver-query / 双向 joint，而不是继续整体替换。

### 损失存在具体的错位

1. `top_focused_pair_loss` 的主项是 top3 对其余方法。top3 内只有 oracle 对当前预测或 SBS 的特定 pair，**不系统覆盖 oracle > runner-up**。这更偏向候选集合质量，而不是前几名内部精排。
2. 相对差值 `(cost_j-cost_i)/mean(abs(cost))` 被 `clamp(0.25, 10)`。0.25 在这个单位下是 **25%**，不是 0.25%。训练集 top3-vs-rest pair 的权重落在该下限的比例，逐问题均值为 **80.18%**；TSP 为 99.93%，CVRP 为 96.71%。大量不同 margin 因而得到相同权重，cost-aware 的程度远弱于表面公式。
3. `winner_balance` 是 CE 类别权重，不是 winner-balanced sampler。它改变自然类别后验的最优决策，可能与原始分布上的 exact top1 有冲突。不能把去偏后的推理分数解释成经过严格校准的概率，但可以作诊断。
4. 损失系数不能跨不同尺度直接比较。R33a 的共享 encoder 梯度探针中，平均加权梯度范数：CE 约 **0.518**、pair 约 **0.0397**、top-k CE 约 **0.0816**、risk 约 **0.000779**。risk 仅约 CE 的 **0.15%**，并没有强力推动 mean cost。范数不代表最终更新份额，但足以说明 0.02 risk 系数的实际作用非常小。

验证集诊断 `score = logits - alpha * log(train_class_weight)`：

| 模型 | alpha=0 top1 / mean cost | 校正例子 top1 / mean cost |
| --- | --- | --- |
| R32e | 46.8000% / 11.187502 | alpha=1: 47.2222% / 11.182626 |
| R33a | 46.8444% / 11.185128 | alpha=0.75: 47.3833% / 11.178893 |

这只是小幅信号，不是突破，也没有在 test 上为这些 alpha 选最佳结果。下一步优先验证普通 CE，再逐项加入直接 winner-vs-runner-up / top1 pair、尺度合理的 cost 项，比继续堆叠多个辅助目标更能定位问题。

## 6. 多问题训练：没有混错 batch，但优化安排需要验证

每个 batch 同一 problem，同一候选池；不同问题在随机轮转中各做一次 optimizer step。各问题样本数相同，所以当前每个问题获得相同 step 数，不存在某问题完全未训练或把不同池硬拼在一起的错误。

但问题等权不等于 family 等权：15 个 MVRP 占 83.33% 的更新，TSP/CVRP/ATSP 各占 5.56%。如果目标本来是 18 问题 macro，这个权重本身合理；它不保证不同 family 的共享表示不互相干扰。

共享 encoder 梯度余弦的三批平均中，跨问题 pair 为负的比例：R32e 47.71%，R33a 43.79%。这是**局部冲突证据，不是负迁移因果证明**；有限 batch 和接近驻点的梯度也可能产生负余弦。应先比较相同预算的单问题与联合训练，或在相同有效 batch/step 预算下测试多个 problem 梯度先平均后更新。不要直接把所有失败归咎于多任务，也不必立即加复杂 PCGrad。相关方法背景见 [Gradient Surgery for Multi-Task Learning](https://arxiv.org/abs/2001.06782)。

效率侧还有一个区别：TSP/CVRP 节点数 50..499，随机 batch=640 几乎都 padding 到最大规模。GPU 高利用率可能包含大量 padding attention，不能等同于有效训练更多；按规模分桶值得考虑，但需要打乱 bucket、保持各规模覆盖且匹配更新预算。

## 7. 数据与评价审计

### 已排除的错误

独立审计按显式 instance ID 将 1,536,000 个 `raw_label.pkl` cost 与 `result_*.txt` 对比，float64 完全一致。没有 NaN/Inf、列错位、缺失/重复/越界 ID、标签长度错误；所有原生 `ind` 与 float64 argmin 一致。

MVRP capacity 虽没有单独输入编码器，但全部实例都是 1.0，当前没有丢失变化信息。L/TW 实例相应字段存在且长度正确。

### 需要改的语义问题：coord_dist

`data.py:_coord_dist_code` 使用 `index // (N // 4 + 1)` 猜测 uniform/gaussian/clustered/ring。实际全部 45 个 MVRP 数据集按客户数递增排列，且没有显式 distribution 字段。函数产生的 train 桶数量是 2501/2501/2501/2497，val/test 是 251/251/251/247，与 README 的分布总数也不一致。

因此可以确认这是**大小相关的索引桶，而不是有元数据依据的分布标签**。未找到原始逐实例生成 manifest，不能报告真实误标比例，更不能仅凭坐标外观猜标签。建议取得原始 metadata；在此之前关闭该分布 embedding 的贡献或设为统一 unknown，并重训验证。它是输入语义缺陷，但尚未证明是 top1 不高的主因。

### 次要评价一致性问题

loader 把 cost 转 float32，会改变极少量几乎完全相同的 cost 的排序：train/val/test 分别有 77/11/3 个原生 winner 与 FP32 argmin 不同，全部是新产生的并列最小值，原生 winner 仍在最优集合中。最大原始 cost 差约 2.37e-7。建议保留原生 winner 标签，并统一 tie-aware 附加指标，但这解释不了几十个百分点的差距。

Val 中 oracle 与第二名差距 <=0.1% 的比例为 7.82%，<=0.5% 为 31.58%，<=1% 为 50.49%。即便只看 margin>1% 的实例，R33a 逐问题平均 top1 也只有约 50.82%。所以不能把主要失败都归因于 near-tie 标签噪声。要判断随机求解器的 label 稳定性，需要同实例重复求解；现有单次离线标签不能给出可达到 top1 的理论上限。

## 8. 下一步顺序

1. **先校正实验与输入协议。** 修正未经验证的 coord_dist，统一 native winner/tie 评价；新增逐轮 train-eval CE/top1、val CE、family 曲线、梯度/AMP step 记录。完整保存 optimizer/scaler/scheduler/RNG，避免续训状态不完整。历史结果保持原样。
2. **先做训练方案对照，不再立即改大结构。** 固定 R33a，至少匹配 12k 更新，允许 60~80 轮上限；验证平台后降低 lr，连续 8~10 次评估无实质 top1/cost 改善再停。上限不等于必须跑满；test 只在方案选定后评估。也可续训 last 验证降 lr 的边际作用，但输入语义修正的正式比较必须重训。
3. **做损失最小消融。** 相同初始化、采样、step 预算：原目标 vs 普通 CE；随后只加完整 oracle-vs-候选、重点 runner-up 的 pair 项，再加按训练 margin 尺度归一化的 cost 项。不要同一次实验同时换 Q/KV、loss、batch 和 feature weight。
4. **验证多任务影响。** TSP/CVRP 单问题与联合训练做对照；必要时测试同 step 聚合多个问题梯度、family adapter。梯度余弦图是提出对照的依据，不是直接采用复杂优化器的理由。
5. **最后再做结构消融。** 在已验证训练配方下，对比无 joint、单向 solver-query、双向 joint；再测同设置有/无 34 维特征。新结构目前未提升，但仅凭本次单 seed、有混杂的对比不能宣判其优劣。
