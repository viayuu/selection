## 简单输入机制

给定 BQ 的复制端点和 LEHD 的单起点执行均指向原物理0，选择器预测的对象应允许写成 \(c_m(X,a)\)：图 \(X\) 上、实际起点为 \(a\) 的方法成本。闭环最优值对循环平移不变，不自动推出有限 greedy 执行的成本也不变。若两个起点产生不同候选成本关系，删除 \(a\) 的置换不变表示便无法区分这两个执行条件。这是条件信息的表达缺口，其影响大小仍未知。

建议仅把 TSP 原补零槽之一赋予 `execution_start` 语义：

\[
z_i=(x_i,y_i,0,r_i,0,0,0,0),\qquad r_i=\mathbf1[i=a].
\]

角色 bit 与对应节点坐标一起进入共享编码，使它能参与节点交互；若先单独汇聚成恒定的 \(\sum_i r_i=1\)，节点与角色的关联又会丢失。项目实现选择 TSP 原补零槽3（从0计数），避免占用被现有全局统计解释成需求或时间窗的槽；这是主线程落实时的字段选择，不是论文中的字段定义。

其中 \(a\) 是生成既有标签时的原物理0；标签及候选池仍按给定 profile 理解。起终同点时，一个 bit 足以表达这项共同角色，BQ 内部复制点也不要求选择器增加重复节点。其它任务沿用各自属性语义，模型其余结构沿用原形式。这个 bit 标记已知 profile 的执行角色，不代表所有候选都以它为起点。

令 \(P\) 为节点重编号，应同时变换 \((X,r)\mapsto(PX,Pr)\)。在共享节点映射、等变 attention 和节点顺序无关读出下，

\[
H(PX,Pr)=PH(X,r),\qquad
u_m(PX,Pr)=u_m(X,r).
\]

前式是图与角色联合的节点等变性，后式是方法 utility 的节点重编号不变性；若使用边或距离矩阵 \(D\)，也随之变为 \(PDP^\top\)。重排后角色必须仍附着原物理节点。重新把新数组第0行标为1会改变执行条件；给每行任意位置 embedding 则额外引入整个序列编号，并非表达这项角色所必需。

canonical 几何 anchor 可按坐标字典序最小值定义。唯一时它是单点；坐标并列时应标记整个并列集合，不能依靠行号打破平局。这只承诺节点重编号无关，不承诺旋转不变。它完全由 \(X\) 决定，可能提供计算便利，却不携带额外的实际起点信息；与物理0不重合时，不能替代真实角色而仍解释为同一执行条件。

## 关键反例与边界

若某方法在不同起点总产生同一闭环的循环平移，则 \(c_m(X,a)=c_m(X,b)\)；若候选间成本关系均如此，补上角色也不会新增 winner 的可预测信息。单 bit 还未概括其余顺序依赖或随机状态。主线程给定的源哈希匹配支持所述 profile 的来源对应关系，未量化起点敏感性及其损失贡献；因此本建议修正输入的语义表达，不能将此缺口称为全部平台问题的根因，也不保证自然 Top1 或真实成本改善。
