## Batch Coupling and Donor Boundary

**No cross-instance routing-capacity/drop coupling is apparent for this pinned configuration.** Node tokens flatten across B/N, but each independently chooses top2; dispatch retains all selected tokens, experts are pointwise MLPs, and batch statistics affect only the separately returned loss ([gates](/public/home/shiys/reld-nco-main/Multi-Task/models/MOELayer.py:271), [dispatch](/public/home/shiys/reld-nco-main/Multi-Task/models/MOELayer.py:392), [MLP](/public/home/shiys/reld-nco-main/Multi-Task/models/MOELayer.py:144)). Eval disables gating noise; `norm=none` avoids batch normalization. This is source inference, not a numerical batch-invariance test. Other branches are unsafe to assume equivalent: expert-choice selects capacity-limited tokens across the flattened batch; soft-MoE mixes tokens across it ([branches](/public/home/shiys/reld-nco-main/Multi-Task/models/MOELayer.py:409)).

Distinguish local RouteFinder's MVMoE implementation: [static embedding](/public/home/shiys/methods论文_mineru_output/source_code/routefinder/routefinder/models/baselines/mvmoe/encoder.py:58) omits O/L while [decoder context](/public/home/shiys/methods论文_mineru_output/source_code/routefinder/routefinder/models/env_embeddings/mtvrp/context.py:51) uses open/remaining-distance flags. [RouteFinder itself](/public/home/shiys/methods论文_mineru_output/source_code/routefinder/routefinder/models/env_embeddings/mtvrp/init.py:133) embeds O/L/depot-TW globally. Its 50/100 checkpoints exist, but exact checkpoint/adaptation compatibility was not established; no need to choose it over pinned ReLD now.
