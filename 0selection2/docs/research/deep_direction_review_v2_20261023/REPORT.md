# 零选择与71%平台：这次具体卡在哪里？

第二轮 Astra 深度研究 · 2026-10-24

**本轮不再只罗列论文方向：将已完成实验、实际训练与前向代码、保存预测中的错误结构放在一起分析。既有GPU实验未被停止、修改或重跑。**

## 1. 先分清两个问题，而不是寻找一个万能修补

**零选择是重要的局部症状，但不是当前全部平台。当前更像是：模型已经学会强条件先验和一部分实例信号，却没有稳定学会剩余竞争关系。** “没有实例信息”“只要扩大容量就能解决”“全是近似并列”“选错checkpoint”“所有模型都只是在过拟合”，这些笼统解释都不足以覆盖现有证据。

本次覆盖历史R35–R104的机制与结果索引，并沿实际继承关系阅读输入、实例编码、双流交互、读出、损失、更新和选型代码；不是声称逐行阅读所有历史文件。新增定量分析使用R89B、R94B、R102A的锁定预测，辅以R84/R90/R96/R103与已完成对照结果。R105/R106只阅读设计接口，不使用尚未正式锁定的中间成绩推导结论。

**主分析参照为R94B**，不逐问题拼接模型。R102A补充说明同口径的更高Top1点及互补性；其cached-feature成绩不冒充完整在线等价/耗时认证。以下数据均为NEW90k冻结版本：18题各TRAIN 81,000、VAL 4,500、TEST 4,500；单一reld_mt、八个B题删除指定三方法；native/FP64 winner。ALL逐问题等权。TEST已参与研发，不称盲测。

| 已完成模型 | VAL Top1 / regret | TEST Top1 / regret |
| --- | --- | --- |
| R89B：优化器参照 | 71.2481% / 0.400676% | 71.4198% / 0.389646% |
| R94B：预训练routing节点融合 | 71.4284% / 0.399079% | 71.5778% / 0.379115% |
| R102A：同routing迁移，TSP/ATSP随机donor | 71.3012% / 0.396175% | 71.5901% / 0.378443% |

这里的regret是逐实例 `(selected_cost - oracle_cost) / oracle_cost` 后按问题平均，不是平均成本之比。旧候选池47.91%与现在约71.5%同时改变了数据和候选竞争，不是同任务上的二十多个百分点进步。

## 2. 零选择究竟解释多少损失？

固定使用R84A validation预先确定的29个严格零选择组与7个近零组。组是“问题×方法”，不是29种不同solver。后续模型即使已经少量选中，仍保留这个固定清单，避免移动目标。

| R94B的TEST错误来源 | 错误数 / 全部错误占比 | regret贡献 / 全部占比 |
| --- | --- | --- |
| 原29个严格零组 | 2,688 / 11.68% | 0.042941个百分点 / 11.33% |
| 原7个近零组 | 1,793 / 7.79% | 0.037476个百分点 / 9.88% |
| 两者合计固定36组 | 4,481 / 19.46% | 0.080416个百分点 / 21.21% |
| 固定清单以外 | 18,541 / 80.54% | 0.298699个百分点 / 78.79% |

**第一项重要结论：只盯LEHD、DIFUSCO或零选择组，不足以解释更大的平台。** R94B共有23,022个错误；清单之外仍占约五分之四。必须同时解决常被选择的方法之间的实例区分，不能再将全18题退化为少数方法的召回优化。

**第二项重要结论：零选择仍值得解决，但其理论预算不能当作可恢复成绩。** 若有答案的离线诊断能无伤害纠正原严格零组全部漏选，R94B的ALL Top1增加3.3185个百分点；纠正36组全部漏选则增加5.5321个百分点、达到77.1099%。这些数字要求事先知道真实winner，且不制造任何新错，绝非可部署上限或成功预期。

当前R94B对36组真实winner仅正确117/4,598，同时误选113次。对R102A是正确135、误选117。让某方法从0次变为100次，并不自动创造净收益；必须检查新增正确减去新增错误，以及两边真实成本。

## 3. LEHD和DIFUSCO不是同一种漏选

下面以R94B的TSP TEST为例；分母是该方法的全部native winner。名次由保存的最终决策分数按原固定tie顺序排列。AUC使用“该方法分数减其余方法最高分”，并非已校准概率。

| 指标 | LEHD | DIFUSCO |
| --- | --- | --- |
| 真实winner / 正确选择 | 762 / 2 | 334 / 0 |
| 实际选择 / 其中误选 | 4 / 2 | 0 / 0 |
| winner在预测Top2 | 344 / 762，45.14% | 39 / 334，11.68% |
| winner在预测Top3 | 669 / 762，87.80% | 90 / 334，26.95% |
| winner预测名次中位数 | 第3名 | 第4名 |
| winner与非winner的margin AUC | 0.6709 | 0.6123 |
| winner实例的选择损失中位数 | 0.5792% | 0.2864% |
| winner实例的选择损失均值 | 0.8613% | 0.5487% |

**LEHD更接近“有一定区分，但难以成为第一”；DIFUSCO更接近“候选本身就没有被可靠提前”。** 同一个固定偏置或相同惩罚同时作用于二者，针对性很弱。LEHD正负margin分布仍明显重叠：winner的margin中位数约−0.788，非winner约−1.122。把整列上移会越过一批真winner，也会越过非winner，不能把AUC大于0.5误解成必然能达到高精确率。

也不能把这些漏选统称为“成本几乎一样，不值得关注”。LEHD被漏掉时的中位损失约0.58%，远非所有实例都在浮点边界上；DIFUSCO也有明显损失尾部。相反，真实并列造成的native错误可能成本为零，需保留原标签并另外说明，不能静默改成FP32 argmin或近优标签来制造准确率提升。

这与R77B旧70114版本的图是同一类现象，但不是同一组实例或相同样本数。详细CSV分别保存新数据与旧R77B，不混用旧70114版与NEW90k版的实例计数或checkpoint。

## 4. 为什么不是“选型规则、数据量、容量”一句话能解释？

### 4.1 按成本选checkpoint，并没有隐藏一条高Top1曲线

| 模型 | 当前锁定点的VAL Top1 | 同轨迹最高VAL Top1 |
| --- | --- | --- |
| R84A | 71.0852% | 71.0852% |
| R89B | 71.2481% | 71.2481% |
| R94B | 71.4284% | 71.4580% |
| R102A | 71.3012% | 71.3667% |

最大差仅0.0654个百分点。因此，“只是一直按成本挑错轮次”不是71%平台的主要解释。这里仅描述已保存VAL轨迹，不重新选checkpoint、不查看新TEST结果。实际代码锁定指标是完整VAL的 `macro_vs_sbs_pct`，不是逐实例actual regret；报告应如实区分。

Top1与成本目标确实不同：Top1理想决策是条件冠军概率最大，平均成本理想决策是条件期望成本最低，actual regret还含随机Oracle分母。R98/R100已有低一点成本但低一点Top1的取舍。然而，这种理论取舍不能替代上表，也不能解释所有失败。

### 4.2 当前大数据的TRAIN也漏选，不能照搬R49的小样本过拟合故事

旧R49的2,000例组可拟合到100%，说明该网络能记忆那批样本；不证明可以从81,000个独立实例中学会可迁移的精细胜负。R90在当前NEW90k的R84A/R87/R88记录中，选中点TRAIN–VAL Top1差约0.16–0.24个百分点，末点约0.25–0.33个百分点。R84A的TRAIN中，DIFUSCO有6,806个winner却零选择，LEHD有14,279个winner而只选择7次。

这里更值得研究的是当前数据规模、监督和表示下的学习可达性，而不是继续增加正则化。“TRAIN约71%”也不证明唯一原因是欠容量：R104扩宽至256和加深至8/4层，TEST为71.1259%和71.3667%，并未超过其历史参照；它们不构成所有容量与训练预算的严格排除。

在本次三个近期锁定模型中，完整TRAIN–VAL差为0.4430、0.5195、0.4767个百分点。特别是R94B：LEHD的TRAIN正确数只有15/14,279、TEST为2/762；DIFUSCO两边均为0。其winner margin中位数在TRAIN/TEST分别为−0.7735/−0.7883、−1.5029/−1.4886，分离失败已经发生在训练样本上，而不是仅在未见实例上突然出现。

### 4.3 81,000不是每种竞争条件都有81,000条

本次读取真实元数据，而不是从索引猜分布。TRAIN按问题、精确N及实际生成字段形成条件单元：TSP有450组、每组中位178例；CVRP有900组、每组中位89例；ATSP有81组、每组约1,000例；多数MVRP有204组、每组约397例。

TSP元数据分布均标为Gaussian；CVRP也是Gaussian，但容量类型有两种；MVRP有uniform、clustered、ring、gaussian_mixture四类。TSP/CVRP具体几何在同一分布名内仍会变化，不能把分布字段相同理解为图完全相同。

这说明某个方法全局有上万个winner，不代表每个局部优势区域都充分覆盖。但也不能反过来直接宣布数据不足：精确N分组人为切细了共享结构，模型本可跨规模学习，且当前TRAIN本身也未拟合。因此，若再扩容，应围绕能定位的竞争区域与难例类型，而非只增加同分布总数。

更具体地，LEHD与DIFUSCO在TSP全部450组中都有TRAIN正例，组内winner中位数分别32和14；但条件多数规则没有任何一组选择这两个方法。CVRP/RouteFinder则不同：900组中只有323组有正例，67个TEST winner中的58个所在组TRAIN正例不足10个。**不能把这三个目标统一解释为长尾，也不能把它们统一解释为已经数据充分。**

### 4.4 模型确实学到实例信息，不能要求它忘掉所有粗粒度规律

R103已在同问题、同精确N内置换完整分数向量，保持各组选择次数。R94B的VAL Top1从71.4284%降至67.7134%，regret从0.399079%升至0.666182%；固定目标选择次数不变时，正确数从126降至平均21.05。故“模型只会背方法分布”不成立。

但该置换没有固定distribution/capacity_type，不能把全部差异称为更细的组合结构信息。规模与约束是合法输入，直接套用去偏论文让模型忘记规模，可能破坏已学到的有效规律。下一步应增加剩余实例信号，而不是把已有先验一并删掉。

本次补算的完整条件TRAIN多数规则在TEST达到69.7198%，R94B为71.5778%；净多对1,505例，来自纠正3,789例、同时伤害2,284例，增益1.8580个百分点。这项净增益不等于纯细粒度结构效应，因为模型也可能更好地平滑估计有限样本条件先验。与先验比较和保频次置换回答不同问题，不能把两个差值直接相减。

## 5. 平台应拆成哪些具体战场？

### 5.1 最难的五题承担过半错误，但不是过半成本损失

| 任务 | 模型Top1 / 条件多数Top1 | 模型额外增益 |
| --- | --- | --- |
| TSP | 47.0222% / 37.6444% | +9.3778个百分点 |
| CVRP | 48.4667% / 33.3778% | +15.0889个百分点 |
| OVRP | 40.4667% / 38.5111% | +1.9556个百分点 |
| VRPL | 37.6667% / 37.5778% | +0.0889个百分点 |
| OVRPL | 41.8000% / 40.6667% | +1.1333个百分点 |
| ALL，全部18题 | 71.5778% / 69.7198% | +1.8580个百分点 |

这五题占剩余错误55.6251%，但占regret39.8157%。TSP/CVRP虽然Top1低，却已取得很大实例收益；VRPL/OVRPL/OVRP主要仍接近条件先验。其余许多题Top1达80%以上，却只略胜条件多数，不能把高Top1解释为已经充分理解实例。

因此，**分类改进与成本改进应并行观察，而不是只挑一个“低准确率题”或一个ReLD方法对。** 一个方案若只救回TSP微小差距，却损坏其余任务的大成本判断，不能算整体突破。新机制应覆盖完整候选选择，报告按任务和成本层级说明从哪里获益。

### 5.2 真正值得优先解释的是有明显成本代价的错误

| R94B全部TEST错例的所选成本超额 | 错误数量 | 对结论的意义 |
| --- | --- | --- |
| 精确0 | 116 | native错误但成本可不损失，不能与浮点口径混用 |
| (0,0.1%] | 1,843 | 与零成本合计仅8.51%的错误 |
| (0.1%,0.5%] | 6,016 | 不应一概当作数值并列 |
| (0.5%,1%] | 5,227 | 有实际选择成本 |
| >1% | 9,820 | 占42.65%的错误，贡献81.58%的regret |

这里是所选方法减Oracle的损失，不是最优减次优的成本间隔。另按真正最优与次优间隔统计，>1%的错误仍有7,599例，>0.5%的错误有12,453例。**所以“所有模型都在猜极其接近的答案”并不符合这份表。** 这也不说明大间隔一定容易预测；它只是排除了将主要代价归咎于无关紧要的并列。

这改变了优先级：不建议把下一轮主要目标设为减少零选择组数；更应解释同条件下的大代价错误，并同时覆盖清单内外的方法。已有cost-sensitive监督并未自动解决它，不能仅把1%的样本再乘一个更大系数便称为新方向。

### 5.3 更换模型经常只是换一批错误

| 相对比较 | 纠正 / 伤害 | 净多对 / regret变化 |
| --- | --- | --- |
| R94B对R89B | 1,756 / 1,628 | +128 / −0.010531个百分点 |
| R102A对R94B | 1,114 / 1,104 | +10 / −0.000673个百分点 |
| R102A对R89B | 1,723 / 1,585 | +138 / −0.011203个百分点 |

三者共同错20,842例，占R94B错误90.53%、regret87.73%。固定36组的4,598个winner中，仅179个被任一模型选对，4,419个全部漏掉。即使知道答案后逐例挑三者中正确的那个，覆盖率也只是74.2691%；这不是ensemble成绩，更不是学习上限。

这削弱了“再平均几个相近模型，便能救回主要漏选”的直接证据。集成与蒸馏只有在模型学到互补信号时才有相应机制依据，不能凭输出不完全一样就假定存在足够互补。[Allen-Zhu与Li，ICLR 2023](https://arxiv.org/pdf/2012.09816)

## 6. 零选择为什么可能长期存在，而平均概率并不低？

### 6.1 出现频率不等于可辨识的获胜区域

设某个当前表示能区分的区域里，三个方法的冠军概率总是(0.45,0.35,0.20)。即使第二个方法承担35%的真实winner，最小化0-1错误的决策仍一直选第一个。平均概率可以准确，第二个方法仍从不被选。

这只是说明“非零winner频率”不强迫最优分类器拥有非空决策区域，**不是认定本数据就是这个例子**。完整实例和固定部署可以确定唯一winner；有限数据训练出的表示未必暴露决定它的结构。因而应研究的是：怎样把某方法的优势实例分开，而不是怎样强迫其有选择次数。[Tewari与Bartlett，JMLR 2007](https://www.jmlr.org/papers/volume8/tewari07a/tewari07a.pdf)

这也解释“128个实例能拟合100%”与大数据仍71%不矛盾。小集合可通过许多并不迁移的细节记忆；数据覆盖增加只有在学习规则能利用相同的优势机制时才必然有机会降低泛化误差，不能从有限集合可记忆推出当前训练配方随数据单调大幅改善。

### 6.2 训练输出有梯度，不等于表示形成了需要的特征

普通CE对winner的输出梯度是 `p_y - 1`，不是“概率接近0就没有梯度”。但参数更新还要经过score对表示及表示对参数的Jacobian；共享特征、样本和损失项在参数空间可以互相竞争。故“梯度非零”只证明没有断路，不证明优化过程正在提取所需的实例关系。

Gradient Starvation分析了特定设定下强特征抑制其他特征的学习；Feature Sieve尝试交替遗忘简单信号。两者给出研究假说，不是已经诊断本模型。特别是本项目的规模、容量和约束是合法信息，不能把它们全部当作应删除的偏差。更合理的研究对象是**保留条件先验，让新增学习专门恢复条件之外的证据**，而不是对所有方法强制均匀。[Gradient Starvation，NeurIPS 2021](https://proceedings.neurips.cc/paper/2021/file/0987b8b338d6c90bbedd8631bc499221-Paper.pdf)；[Feature Sieve，ICML 2023](https://proceedings.mlr.press/v202/tiwari23a/tiwari23a.pdf)

### 6.3 同方法AUC和最终argmax是两件事

CVRP/RouteFinder在R94B中的margin AUC达到约0.8714，却仍未正确选中67个TEST winner中的任何一个。正例比该方法自己的负例更高，不保证高过当前实例的其他方法。LEHD的AUC约0.67，也不能支持无伤害上调其整列分数。

因此R81式同方法正负排序、R82式同条件regret排序可以检验一种区分机制，但不自动完成跨方法冠军概率的对齐。全局温度更不能修复argmax：同一实例所有分数除以同一个正数，第一名不变。每方法不同温度或偏置会改变边界，但是否正确必须由自然分布下的精确率和成本回答，不能从“选中了几次”反推成功。

## 7. 实际计算图里，哪些限制是真的？

### 7.1 当前主路径不是源码Embedding，也不是只给模型几个统计量

R77/R84继承的基础路径实际为：原始节点/有向矩阵、真实规模与任务条件，加局部几何；四层节点attention；ID+34维方法特征；两层同步双流；节点mean/max汇总为h；h以单query读取方法得到共同context；每方法交互token与h、context一起进入共享MLP，生成utility。

源码依据：`V4Model.py:122,236,270,288`、`dual_stream.py:10,31,93,98`、`pairwise_selector.py:11`。这里保留完整坐标、需求和启用的L/TW字段；ATSP完整有向矩阵进入bias，没有对称化。方法token在双流后已随实例变化，不能把它说成仅一条静态向量。旧协议中的`query_num=4`不是该实际路径有四个query的证据。

另一方面，有向矩阵进入bias与进入可携带拓扑信息的消息内容不是一回事；节点mean/max也不能凭自身保留所有组合关系。维度128或mean/max存在，并不能单独证明丢了与winner有关的信息，需指出具体被混淆的对象。

### 7.2 一个严格但局部的ATSP反例

两张六节点完整有向图，所有非对角成本先置为2。图A把六节点单环上的边改为1；图B把两个独立三节点环上的边改为1。二者原矩阵不同，但每节点行/列统计、全图统计和每行bias值的多重集相同。

在基线中，所有物理节点初始value相同；不同边权只重新分配这些相同value的权重，各特殊token收到的总权重也相同。归纳到多层，节点表示仍不能区分两图。实际四层编码器、三个随机seed的CPU检查，输出差异在约1e-6浮点量级；R92的357维统计对两图也完全相同，而1成本边构成的三步闭合游走数分别为0和6。

**这是“完整矩阵已输入，但某类拓扑仍不可辨”的结构证据，不是当前平台的原因认证。** 未证明真实数据存在这些碰撞、候选winner因此变化、或它影响多少错误。R102/R106的MatNet节点身份value打破了此反例前提。更不能将ATSP六节点反例推广到带坐标的TSP/CVRP，或据此宣称换高阶GNN必然提高全部18题。

它能严格否定的是一个过强说法：“既然输入了全图，增加宽度/深度总能恢复所有信息。”对强制合并的结构，宽深不解决相同值聚合的对称性；对一般连续实例，更多层可能仍有用，当前证据没有全面排除。

## 8. 损失与优化：哪些推导成立，哪些不能归因？

### 8.1 maximin没有在推理时禁止某方法获胜

设utility按降序为u1、u2、…，至少两个合法候选。原成对分数只是 `u_i - u_j`，所以maximin后的第一项为 `u1-u2`，其余为 `u_i-u1`。因此排序和argmax与原utility一致，第一、第二名的分差却被加倍。删除maximin、在同一固定checkpoint上重取utility argmax，不会突然救回LEHD。

概率与梯度确实改变。记maximin softmax的CE梯度为 `g_i=p_i-1[i=y]`；在无并列、固定局部排序时，对原utility的梯度为第一名 `2g1`、第二名 `g2-g1`、其余 `g_i`。错误的第一名并没有因maximin而得到零梯度，真实winner在较后位置也仍有纠正梯度。这个变换在不限utility时可以表达任意合法的内部概率分布，不能由此证明某个类永远不可能被选择。

这使概率链接成为一个真实优化差异，但R91已经改变相关链接，R93也去掉pair/risk/R-Drop、使用单次前向的纯utility CE；这些实际版本没有解决平台。故“删掉maximin就能修复零选择”证据不足。不能以公式中存在梯度耦合，跳过已做实验直接认定它是主要原因。

### 8.2 联合监督不一定在同一标尺上

二方法示例最清楚：utility差为d，maximin CE使用的二分类logit为2d，pair logistic使用d。若某表示区域的真实胜率为eta，二者各自概率拟合的最优d分别为 `0.5*logit(eta)` 与 `logit(eta)`。它们可要求相同的符号，却要求不同的置信度；多方法再加入成本risk与Dropout一致性，目标不再是单一冠军概率拟合。

这不是一个普遍“loss写错”的结论。纯CE版本也没有突破；risk降低期望成本与提高Top1可以有取舍。R-Drop约束的是**同一步、同一组参数下两次Dropout**，不约束不同训练轮的输出不变。按默认损失项系数比较数字，也不能替代各项的实际参数梯度。

同样，“所有pair胜率都学好”也未必唯一确定冠军分布：不同全排名联合分布可能拥有相同两两边际，却有不同第一名概率。R100的pair-Borda和冠军分类不能凭模型名字认作等价目标。本项目仍有native CE提供冠军监督，因此这不是其完全缺少冠军信息的证据。

### 8.3 这次没有发现一个统一的更新阻断

实际路径使用成功更新计数，逻辑batch按真实行数加权，AMP失败重放同一批；microbatch不能简单按块数平均，尾块必须按样本数加权。跨实例目标需完整batch语义，R81/R82采用的重放机制与普通row loss有不同要求。本次读取了相应实现，并用小型CPU代数检查说明公式边界，未重放历史训练、未对全部历史运行作逐字节认证。

学习率、裁剪、AdamW/Muon、warmup、自然采样与历史早停都可能影响所学解；但已有batch/LR、ScheduleFree、SAM、PCGrad、Muon与样本曝光等不同尝试，不能继续说这些方向完全没碰过。R89的优化器对照及R94的预训练对照有小幅正收益，也不能把整个历史写成全部失败。当前证据更支持：**已试的单个修补不足以产生所需的区分，而不是优化技巧没有任何价值。**

### 8.4 三个容易被总体日志掩盖的实际细节

**一次更新是单题1024例，不是18题联合batch。** 当前主干预算57,600次成功更新，均分为每题3,200次；warmup4,320、每1,440次VAL，固定cosine降到1e-6，没有VAL驱动早停/LR重置。共享AdamW的动量/二阶状态在不同问题间交替累积；等量曝光不等于各任务在参数空间拥有等量有效更新。R64/PCGrad和R69私有化已经涉及任务干扰，因此不能将这个事实重新包装为“从未尝试的多任务冲突修复”。

**候选数改变监督几何，但pair数量已归一化。** K=3时true3、pred3、all三组基本都是全池；K=10时focus pair与其余pair权重不同，CE基准量级也随log K变化。不能简单说“大池有更多pair，所以loss自动大K²倍”，也不能把相同系数视为相同参数梯度。它是待区分的任务折衷，不是已证明的主要原因。

**日志名相同不保证量相同。** R93用utility CE训练，但保存的eval CE仍按maximin计算；它与训练CE不是严格同一量。完整训练存在少量AMP重试，例如R84A累计25、R89B26，不能把启动期0重试写成全程0；实现对同一batch重放，不能把有重试解释成大部分更新丢失。R93末期裁剪前gradient norm区间均值约0.44/0.53，仍非0；这既不是收敛证书，也不是裁剪长期把学习堵死的证据。

## 9. 我会保留哪两个具体研究方向？

这不是新的四卡启动指令。正在运行的FFN专家和native encoder微调保持原计划，待其唯一锁定模型交付后再合并证据。下面是下一阶段可检验对象，不预设收益，不追加一串参数搜索。

### 方向一：把条件先验与实例证据分开学习，但保留自然分布

**对象是零选择及整体条件外区分；优先级低，保留为定义清楚的备用假说，不据此立即再开一组loss实验。**

令g为推理前可得条件，pi(m,g)为TRAIN拟合、平滑后的条件方法先验。最稳妥起点只用当前输入已有的问题类型与真实规模；若加入分布或capacity_type，须先固定LIB/未知来源的推理可得性与回退，不能借额外输入伪称纯损失收益。

学习残余证据t(x,m,g)，最终方法分数为：

```text
s(x,m) = log pi(m,g) + t(x,m,g)
最终单方法选择 = argmax_m s(x,m)
```

重点不是这条加法。直接加先验或减先验，R66/R78等已经触及，且自由网络能吸收常数。真正可检验的改动是**正对使用TRAIN真实的(x,winner)，负对使用相同条件内独立组合的实例与方法**，学习实例与方法之间超出条件先验的关联。

正、负各半时，理想logit满足：

```text
t*(x,m,g) = log P(Y=m | x,g) - log pi(m,g)
```

无需B×B大队列。给定同一实例，合法方法数量只有几种，可把负项精确求和：

```text
L_ratio(x,y) = 0.5 * softplus(-t_y)
             + 0.5 * sum_m pi(m,g) * softplus(t_m)
```

这是联合分布对独立分布的density-ratio分类，借鉴对比似然比学习；不是把所有非winner当同一种负例，也不是要求各方法均匀获胜。[Durkan等，ICML 2020](https://proceedings.mlr.press/v119/durkan20a.html)

**必须补回先验。** 若仅取t最大，就是按lift选择，可能偏爱罕见方法而破坏自然分布Top1。负正采样比不是1时还要补回相应常数。pi只来自TRAIN，当前query的winner只用于loss，不进入前向；已有R77/R84输入与完整候选池不变，学习贯穿表示网络，不是在冻结输出上再拟合偏置。

负对允许恰好抽到当前真实winner；排除它会改变独立乘积分布，上述密度比公式便不再成立。自然pi也意味着稀有方法的总曝光仍低，并未自动提供更多稀有正例。仅把普通CE的logits写成`log pi+t`而不改变目标，是自由网络可吸收的重参数化，不是本方案所称的density-ratio训练。

**与旧方案的差别及局限：**R81优化同方法正负AUC；R82优化同条件regret顺序；R85 OVR的标准负类来自“不属于该类”，而这里负对按固定pi独立组合。这里用一个有明确恢复公式的概率比把同方法区分与跨方法选择接起来。但理想总体决策与正确训练的CE相同，**既不扩大Bayes信息，也未证明优化更容易**。它可能只是另一种低效重参数化，不能包装成已经解决梯度饥饿。

研究应回答：训练出的残余证据是否在同条件内将真实winner推到第一，同时保持非winner误报低；是否改善固定清单之外的完整任务。若t只学出条件常数、仅改善AUC而不改善选择，或再次以误选换选择次数，就停止该方向。若同时加入成本监督，须明确density-ratio理想解不再自动成立，不能用纯目标的证明替混合目标背书。**Astra损失分析支线据此将它降级：当前没有足够机制证据优先于已试CE/OVR，仅有“目标可精确定义”还不够。**

### 方向二：改变关系计算的内容，而非再加一层attention

**对象是全18任务的组合关系学习；有结构性动机，但目前缺少与真实solver优势的直接联系，不能立即当成主因。**

当前许多变体改变节点消息权重、宽深或读出，仍让网络自己从加权聚合中学会“哪两条边在同一中间客户相连、其容量/时间如何组合”。可以研究显式短路径与资源状态：保留有向片段 `(i,j,k)` 的共同中间节点、两边长度、方向/闭合信息、需求组合和已核实的时间/长度状态，而不是只保存两个邻居集合的平均。

| 任务类型 | 可以保留的输入可计算对象 | 不能冒称 |
| --- | --- | --- |
| TSP | 两边连接、局部替代连接、短环/闭合及几何对应 | 已得到solver最终路线或全局最优结构 |
| ATSP | 有方向的连接组合，而不是行列分位数或对称距离 | 任意有向图都已充分表示 |
| CVRP | depot相关连接、需求组合、容量余量的局部条件 | 局部通过等于完整路线可行 |
| O/L/TW变体 | 开放返程计费、长度累积、等待/服务/窗口组合 | 原生约束未核实部分已统一 |
| B变体 | 仅已锁定且核实的当前载荷状态语义 | 默认引入经典先送后取或重定义旧标签 |

固定短组合步骤，不进行完整路线构造、不运行底层solver，不读取真实路线。片段内容作为值进入候选条件化聚合，最终仍只输出完整合法池的方法分数。原输入、ID及合法规模信号保留。稀疏k邻域可把片段数控制在约O(Nk²)，但距离构造、候选读出和真实耗时仍需计入；不是宣称免费或可以保留全部N³片段。

PathNN提供“保留路径身份而不是只增加邻居传播”的研究依据。它的具体理论图类、路径集合与本项目不同；欧氏完整图最短路径常退化为直接边，不能照抄最短路模块便期待改善。[Michel等，ICML 2023](https://proceedings.mlr.press/v202/michel23a/michel23a.pdf)

**这里真正新增的是可组合的关系内容和对应关系**，不是R56已有edge token、R63已有workspace、R92已有层次化、R99已有两跳传播的改名。它也不重走R54/R55的路线标签重建：没有新增结构标注，没有连续边差累加的标量捷径目标。

开跑前只需要一条实质理由，不需要新大型审计：现有保存案例中，这类被平均掉的关系，是否确实与某些同条件下的候选优势有关？如找不到，应保留为未验证研究对象，不凭六节点反例马上再训40轮。若存在，则后续应该做“保留/删除同一明确关系内容”的匹配比较，而非同时换encoder、loss、donor和预算。

**两者的优先顺序不是按标题排列。** 当前先等既有R105/R106完成既定交付；如果需要选择新的研究主线，更值得继续论证的是方向二的“关系内容与真实优势之间的联系”，而不是先启动方向一的替代surrogate。若这条联系仍找不到，本报告宁可保持“暂无证据足够强的新训练方案”，也不再拿四个新名字填满实验列表。

### 数据方向何时优先？

对CVRP/RouteFinder这种局部正例稀疏的方法，定向覆盖合理；对全部450条件组都见过正例而TRAIN仍几乎零选的LEHD/DIFUSCO，先扩大总量的证据较弱。只有当新增关系或目标能够在某些优势区域拟合TRAIN、却在同条件留出区域明显失效时，才更有理由围绕这些区域补充独立实例。当前不生成新数据、不补求解标签，也不改变冻结划分。

## 11. 下一轮成功应当意味着什么？

**零选择方向：**固定原29/36组，不随新结果更换清单。按方法分别报告真实winner召回、选择精确率、误选次数和真实成本；特别分开LEHD式Top3内漏选、DIFUSCO式未提前、极稀少组。只减少零选择组数或只提高AUC，不算成功。

**整体方向：**所有18题与完整候选池保留。报告清单外80.54%错误、五个困难任务、其余任务，以及成本损失层级的纠正/伤害。Top1、actual regret、mean_cost必须同一个锁定模型同时看，不逐题拼接，不靠某一任务的好点覆盖其他任务退化。

**证据方向：**从头、相同数据和初始化/预算的匹配对照才能归因；已完成历史参照只能提供方向。训练/选型使用TRAIN/VAL，唯一checkpoint和规则锁定后报告TEST/LIB。当前TEST已经参与多轮研究，不能再称完全盲测。若只是继续0.1–0.3个百分点波动，不把它包装成解决平台，也不自动追加多seed、阈值和系数网格。

本次主要改变不是再给四张卡安排四个名字，而是先把两类目标分开：**零选择需要方法优势证据越过竞争者；71%平台需要在主要错误区域中形成新的、可迁移的区分。** 两者相关，但损失预算、数据支持、代码机制和停止条件都不同。
