## 3. 平台期到底体现在哪些目标上？

### 3.1 指标定义与比较边界

对题目 t 的合法候选池 K_t，原生成本为 c_ik，预测选择为 a_i，保存的 native winner 为 y_i。定义：

\[
o_i=\min_{k\in K_t}c_{ik},\quad
b_t=\arg\min_{k\in K_t}\operatorname{mean}_{i\in TRAIN_t}c_{ik},\quad
\mathrm{Top1}_t=100\operatorname{mean}[a_i=y_i].
\]

\[
\mathrm{vsSBS}_t=100\left(\frac{\operatorname{mean}c_{i,a_i}}{\operatorname{mean}c_{i,b_t}}-1\right),\quad
\mathrm{vsOracle}_t=100\left(\frac{\operatorname{mean}c_{i,a_i}}{\operatorname{mean}o_i}-1\right),\quad
\mathrm{regret}_t=100\operatorname{mean}\left(\frac{c_{i,a_i}-o_i}{o_i}\right).
\]

SBS 在完整冻结 TRAIN 拟合；不是 TEST 上事后选择。ALL 为十八题等权，不能将不同单位的 raw cost 混合后再作比。表中的 ALL mean_cost、SBS cost、Oracle cost 仅是相应题均值的描述性平均。`vsSBS` 越负越好，`vsOracle`、actual regret 越低越好。后两者分别是均值比和逐例比的平均，不互换。

winner 为锁定 cache 的 native int64 `ind`，已核对原 FP64 argmin，不能用 FP32 argmin 静默替代。严格 Top1 与 tie-aware Top1 是不同量；本文 Top1 使用前者，近乎相同成本的改选仍可能改变严格 Top1。候选名映射、原生预算、精度和 tie 规则共同定义被学习的目标。

R109 预锁定按最小 whole18 VAL macro_vs_sbs 选型；R112/R113 按最大 VAL macro_top1，完全并列再按最小 actual regret、再取最早 checkpoint。下面保留这种差异，不按新结果反选所有臂。数据冻结为每题 TRAIN 81,000 / VAL 4,500 / TEST 4,500、seed2，旧 10,000 例不混入。八个 B 问题删 RouteFinder/MoSES_RF/MoSES_CaDA；RELD_MTL 删除、RELD_MOEL 原值映射为 `reld_mt`，不取两者最小值。LIB 使用各自旧 native 数据与对应合法池，不能把它与新 TEST 称同一分布。

## 4. R114：有真实响应，学习收益尚待检验

### 4.1 这份 pilot 的分母

最终合并为 16 个 demand/TW 适用问题 × 32 TRAIN bases = 512 个题内基础实例；2048 个端点实例、9600 个候选成本值、1536 个完整候选池响应对。CVRP 修订部分为 32 bases、96 endpoints、64 pairs、960 cost entries。TSP/ATSP 没有新增响应。相同 base 的端点、需求干预与 TW 干预相互相关，不能把 9600 个成本标量当成 9600 个独立实验。

当前阶段是 **ACQUISITION / response pilot**：没有训练响应函数模型、没有响应学习后的锁定 VAL checkpoint、没有相应 TEST/LIB。`complete_labels` 只表示本次限定采集对象完成。原先允许 partial-negative closeout 的制度仍正确，但不应该在已经完整的合并终点继续称缺标签；也不能越过采集到学习这一缺口。

### 4.3 从信号到效用还差三步

第一，响应可能只是公共尺度变化。预测所有候选一起变贵，未必有助于区分谁应当被选。应关注中心化候选相对响应，以及对候选排序/成本差有影响的部分。

第二，响应必须能由合法输入预测。测得某个变化大，不代表看见需求/TW/几何就能泛化预测它；32 bases/题不足以证明跨 base 的可学习性。学习器若依赖查询端真实成本才能工作，就违反部署条件。

第三，即使预测响应较准，也可能只改善远离冠军的候选或近乎无代价的 ties。最终必须改善冻结分布上的 mean_cost、actual regret 或 Top1 的预声明目标，且不产生更贵的误选。已有数据可支持一次小而有限的学习检验；不支持直接追加许多 NN 臂。

### 5.2 为什么正 winner 频率可以对应零选择？

即便真实后验 p_k(x)=P(Y=k|X=x) 处处正，也可能每处都低于另一候选，因而 k 从不成为 argmax。例如恒定后验 (0.45,0.35,0.20) 中第三类有 20% 质量却不应获得 20% 选择配额。对我们的确定性/随机性混合运行条件，这只是一个数学可能性，不是已确认真实后验。

也不能用低 ECE 结束讨论：一个只输出类别先验的模型仍可校准。完整输入后验与基于粗化表示的校准概率不同，[Evaluating model calibration in classification，Proposition 1、§3.1](https://proceedings.mlr.press/v89/vaicenavicius19a/vaicenavicius19a.pdf) 给出这一严格区分。另一方面，[DFR，§4–6](https://arxiv.org/html/2204.02937) 在特定伪相关基准发现，坏预测背后仍可能存在可读出的有效特征；这反对“漏选必然说明特征没学到”，却不证明本项目已有同样特征或允许使用 VAL 标签重训。

本次同一统计口径下，89 个合法题×候选组合中的 native-positive、exact-zero-selection 数分别为 R109 A/B 22/19、R112 A/B 20/22、R113 A/B/C 35/33/35。这些不是固定 36 个弱召回目标组。后者在 R109 TEST 有 4598 个 winner 实例，召回由约 0.674% 到 1.762%，救回 57、失去 7、新误选 105；这些集合不是互斥的整体错误分解，不能作 57−7−105 得到 ALL 收益。

更强的“漏掉可学习区域”证据应是：仅从合法输入确定的区域，在排除同 base 后重复出现；锁定预测规则在同分布留出上净救回并改善成本；同时记录从其他赢家吸走的错误。真实 winner 直方图与模型选择直方图各自有用途，但不能互代，更不能把真实 winner 柱当成 100% 模型准确率。

### 5.3 R57 还约束哪些说法？

R57 静态覆盖 128 个合法题×候选组合；原输入 runtime 只完成 31/128，重现的 992 个成本不能认证未存档的全部历史依赖修订。历史 B 任务的 signed-residual-load 与 classical backhaul 可行域不同；在旧检查中，大量路线通过前者而不通过后者。它揭示语义边界，不等于当前冻结版本的标签均错误。

旧 R45A VAL Top1 49.1167%，条件多数先验 42.4667%，同题同 size 置换均值 39.7110%，说明旧版本确有实例信号；其循环置换并非均匀随机排列，分位数不是总体置信区间。这些旧数据/候选池数字不估计当前 90k 的 71% 平台。未闭合的 TorchRL ABI、NSS 导入、RF/MoSES 绑定等历史问题只按其覆盖范围保留，不给它们添加未经证明的“平台原因”。

## 7. 四个方向：改变什么对象，怎样被证伪？

### 7.1 所有方向共同遵守的设计边界

以下均为未来研究建议，不是已启动或自动排队的协议。现有 R109/R112/R113/R114 的 loss、超参数、初始化、标签、backend、预算、checkpoint 和推理规则保持锁定。新版本复用 R84 的 TRAIN-only 统计、fresh 随机初始化和合法输入缓存；不把旧训练权重当 fresh。默认逻辑 batch1024 是起点，函数 episode、成对 base 或长上下文可以采用有科学理由的不同 batch，但必须说明样本单位、全逻辑 batch 的目标及归一化，不能将 microbatch 当成相互独立的 batch。R113 已锁定 batch512 不因此改变。

所有监督只来自冻结 TRAIN 或另存的新 TRAIN 派生标注。新标注使用单独版本号，记录 base ID、干预、原生配置/精度/预算/seed、适用 mask、实际运行成本和失败状态，不覆盖原 90k 成本与 winner。查询的标签、成本、winner、在线 solver 输出均不进前向；历史 TRAIN 上下文可以包含特征和标签。训练查询及其所有关联副本从上下文排除；VAL/TEST/LIB 标签永远不进 bank。参考数据的选择和索引只用合法输入，不能用待预测 winner 作检索键。

未来每臂先锁定一个 whole18 VAL 选型准则及固定推理规则，再作完整 TEST/LIB，并并列报告 VAL、ALL 与各题七项指标。D1/D2/D4 建议主准则为最小 whole18 VAL macro_vsSBS，完全并列再最小 actual regret、再最早 checkpoint；D3 为最大 VAL macroTop1，完全并列再最小 actual regret、再最早。**这些是新版本建议，不修改已有臂的选型标准。** 以下收益门槛是事前拟议的实用效应门槛，不是已做 power analysis 的显著性保证。

对成本主线，建议进入后续独立确认的最低信号为：相对本轮 fresh 匹配对照，VAL actual regret 与 vsSBS 各至少下降 0.005pp，Top1 不下降超过 0.10pp；任何单题 actual regret 增加超过 0.05pp，都要按失败的共同改进门槛处理并完整披露。它允许一部分微小题内波动，但不允许 ATSP 的收益掩盖另一题的大损害。对一个只覆盖四题的 pilot，另外报告四题等权效果，不能仅因四题平均改善就称 whole18 达标。

TEST 已部分参与历次研发，本报告又使用它研究方向，所以不是全新盲测。未来 TEST/LIB 只在版本锁定后用于评估；若出现损害，记录失败，不回调 checkpoint/温度/规则。最终研究结论宜用未参与方向研发的独立数据确认；本文不创建新划分，也不将重新命名现有 TEST 视为独立确认。

GPU-hours 均按**两张 RTX3090 卡时相加**，不是“机器小时”：总 G 卡时在两卡完全并行时理想墙钟为 G/2，真实墙钟会因串行标注、CPU/I/O 和资源排队更长。下文为保守量级估计及硬上限，未做新吞吐测试，不能视作测得运行时间。若未来执行，仍只能使用 gpu03/job1465 和既有授权两 UUID：`GPU-cb24f168-9f18-f0d5-6f4a-6d2406958f50`、`GPU-cb626bdb-4319-2f5e-b91f-17fcaa44a83d`；不能据此新增资源或占用 owner 的队列。本文估算不产生资源占用。

### D1（优先级 1）：真实干预响应算子，而非只增加独立点标签

**问题与数学对象。** 将一个适用实例写为 X=(g,u)：g 为几何/图及不随本干预变化的条件，u 为 demand/TW 等资源字段。令 s_t>0 为 TRAIN-only 固定尺度，监督对象为中心化相对成本

\[
z_k(g,u)=\frac{c_k(g,u)-K_t^{-1}\sum_jc_j(g,u)}{s_t},\qquad
\Delta z_k=z_k(g,u')-z_k(g,u).
\]

中心化去掉所有候选共同涨价的分量；s_t 不依赖查询成本。最小化条件期望 z 与最小化同题条件期望成本的候选次序一致，但不等同于最小化逐例除以 Oracle 的 actual regret，所以仍须两者实测。

要检验的计算对象是一个**有限响应转移算子**。由输入确定一个合法参考 u₀ 和到 u 的固定四段路径；模型自行预测锚点相对成本与状态，再沿路径推进：

\[
(h_0,\widehat z_0)=A_\theta(g,u_0),\qquad
(h_{j+1},\widehat{\Delta z}_j)=T_\theta(h_j,g,u_j,u_{j+1}),\quad
\widehat z(g,u)=\widehat z_0+\sum_{j=0}^{3}\widehat{\Delta z}_j.
\]

选择 `argmin` 预测相对成本，tie 规则训练前固定。参考实例和路径全部由查询输入构造，**没有** u₀ 或任何路径点的真实求解结果。几何编码复用，转移模块较小，部署保留四段计算，而非训练时加一个最后被丢弃的辅助头。用有限差分而非默认可微梯度，是因为原生离散求解响应可能跳变。若实现最终只是同一个标量网络的梯度积分，严格退化为端点回归，应如实降级，不能另起“算子”标题。

**信息权限与范围。** 第一版只在 CVRP、VRPL、OVRPL 的 demand 和 OVRPTW 的 TW 构造上述路径；其余题使用共同端点预测路径，仍由一套全局模型和 checkpoint 输出全部十八题。TSP/ATSP 没有新响应监督。参考点、每段原始字段、native 输入合法性与部署成本必须在未来版本中定义清楚；无法构造合法参考的任务不强行加入。R114 的 512 bases 可以训练/评价 TRAIN 内的跨 base 响应预测，不得把 self-context 或同 base 端点泄漏当泛化。

**与历史的真实差别。** 这是旧 MP2 尚未执行的函数学习阶段，不是首次提出“响应”概念。区别于 R39/R85 的点式成本目标、R71 的点式联合分布，也区别于 R113 的合成短程序：监督和推理对象直接描述原生候选成本随输入条件的有限变化。它仍可能等价于更昂贵的点式拟合，因此必须接受下述对照，而不能用名字逃避既有反证。

**唯一关键模型对照。** 两臂使用同一 fresh carrier、全部相同端点/成对标签、初始化、参数量及样本曝光预算。A 为静态端点模型：同样执行四次等预算状态更新，只看待预测端点，其两端输出之差也接受相同成对目标；B 在同一计算预算下沿固定输入路径推进并累加预测响应。两者都可以看到历史 TRAIN 的监督，查询前向都看不到标签。这样区分的是部署时的响应计算，不把“B 多拿了成对标签”当机制收益。A 不是故意给错配对的弱对照。

数据采集问题单独在前置 pilot 中解决：同一个 TRAIN base 上，定向与随机使用相同变化节点数、同一可行域条件和匹配的实际幅度；预先固定幅度容差（拟议 1%），无法匹配时记录并排除该配对，不依据返回 winner 删除难例。运行次序交错、原生预算/随机条件相同。此对照只测方向带来的差别，不把它同时扩展成四臂 NN 网格。[COAL 的决策相关查询规则](https://proceedings.mlr.press/v70/krishnamurthy17a/krishnamurthy17a.pdf) 是设计启发，不授权把未标注候选当已知输家；此轮仍采完整合法池。

**有限计划与费用。**

1. 先复用现有 R114 数据，固定两折、按 base 成组的 TRAIN 内交叉预测；同一 base 的所有 family/endpoints 必须在同侧。这只是 TRAIN 内学习检验，不修改冻结 TRAIN/VAL/TEST 成员。只比较一个预定的线性响应预测器与两个简单对照（零响应、训练折题×family 平均响应），不做超参网格。对象是预测 Δz 的误差及候选次序变化，最多 8 CPU-core-hours，0 新标签、0 GPU-hours。它不能认证神经算子，只能决定小 pilot 是否值得继续。
2. 若跨 base 预测至少在 CVRP-demand、VRPL-demand 两个预声明正信号条件上，将 MAE 相对两个简单对照各降低 10%，且 OVRPL-demand、OVRPTW-TW 两个反例条件没有超过 10% 的 MAE 损害，再建议一份新标注版本：四题各 64 个尚未用作该 pilot 的冻结 TRAIN bases，每个 base 采原点、匹配定向端点、匹配随机端点。四题候选数为 10/6/6/6，故上限为 256 bases、768 endpoints、512 response pairs、**5376 个候选成本值**。标签 GPU 上限 10 卡时；达不到匹配或完整池则交付显式 partial，不强改 backend。
3. 下一独立实验调用才可考虑上面的两臂，seed2，各至多 20 次完整 TRAIN 曝光，加同样次数的派生 base-group 曝光；成对端点保持组内语义。预计训练/固定评估合计 32–56 卡时，硬上限 56；加标注总上限 **66 卡时**，两卡理想墙钟不超过 33 小时。CPU 额外约 16–32 core-hours，增量磁盘建议不超过 25 GB，复用输入缓存后的读写量按 50–200 GB 留预算。标注耗时为估计，不根据“9600 个标量”臆测原生 backend 一定很快。

**收益、损害、证伪。** 主要收益是成本主线门槛，同时关注四题的 actual regret、Top1、vsSBS 和 winner-flip 的预测价值；R114 RMS 大不算收益。记录路径端点误差、锚点误差、累积误差、推理 p95 与峰值显存；相对既有点式部署延迟超过 3 倍即不推荐部署。B 在相同标签下不胜 A，或只有响应 MAE 降低而成本不改善，便否定这一实现的实用机制。跨 base 简单检验不通过则本轮止步，不把它升级为“任何响应学习都不可行”。

**最强反方与改变推荐的条件。** R114 定向幅度更大、局部样本少；真实 backend 可能有跳变和路径依赖；预测锚点可能吞掉全部收益；离线响应数据可能与正常 TEST 分布相离。若同幅度随机也同样有效，后续应优先便宜的随机采集，不继续神化“机制定向”；若静态 A 相同或更好，保留端点数据价值并撤销响应计算路线。正推荐必须来自锁定模型的真实决策收益，不来自更漂亮的响应曲线。

### D2（优先级 2，暂缓）：让历史 TRAIN 结果参与结构形成的条件函数学习

**对象。** 令 C={(X_j,z_j)} 为合法 TRAIN 上下文，学习的不是单点映射 f(X)，而是函数族上的条件算子

\[
\Omega_\theta(C),\qquad H_X^{\ell+1}=F_\theta^\ell(H_X^\ell,\Omega_\theta(C)),\qquad
p_\theta(k\mid X,C),\ \widehat z_\theta(X,C).
\]

上下文的原始结构与成本标签在生成 Ω 前成对绑定；Ω 在查询图尚未全局池化前进入节点/候选关系计算。部署是一次有限的条件推理，不更新查询标签，也不运行查询 solver。数学上这仍是监督学习，只是学到“如何根据样本集构造预测函数”；随机 episode 不意味着创造新的任务或独立数据。

**范围与权限。** 覆盖全部十八题；每次固定 32 个同题 TRAIN 上下文，建议 16 个输入近邻加 16 个 seed2 固定抽样，索引只依赖合法输入；A/B 使用相同上下文。TRAIN 查询排除同 base 的所有相关副本；context 可含历史成本，query 的成本只在训练目标侧出现。部署 bank 仅含冻结 TRAIN，更新 bank 会形成新推理版本。每个上下文图先压成有限的结构 token，再与查询交互，不把 81k 个完整图直接全连接；这项压缩本身也可能成为瓶颈。

**为什么不是重跑 R47/R97。** R47 已有可训练检索 key、label value 与差分修正，不能声称过去只是固定近邻。R97/98/100 已在大 TRAIN bank 和固定特征上分别尝试分类、成本/两两读出。此方向必须实现“历史输入与结果共同改变查询的结构表示”，才不同于这些已完成版本。[ANP §2–3](https://arxiv.org/html/1901.05761v2) 支持 query-conditioned 的函数对象；[TabICL App.A.1](https://arxiv.org/html/2502.05564v2) 则清楚区分晚 label fusion 与早融合。但前者的函数族假设、后者的表格预训练先验均不能自动迁移到 routing。

**决定性对照。** 两臂同样 raw graph 编码、同一个上下文集合、同样标签与容量：A 先完成查询编码，仅在最终读出接入 context；B 在查询结构层之前/之中接入 Ω。A 仍是可训练强上下文模型，不弱化为简单多数票。编码层数、上下文 token 数和总样本曝光相同；报告实际 FLOPs/时间差异，参数相等不足以称计算完全匹配。只改进入位置，不能同时更换标签目标、检索策略、预训练源和 bank 大小。

**有限计划。** 无新 solver 标签；一份全18共享模型的两臂 seed2，各最多 20 次完整 TRAIN 曝光，32 context 固定，逻辑 episode batch 拟议 128 queries；microbatch 保持 base 排除及归一化。训练前在 TRAIN-only 固定输入缓存/索引构建上限 16 CPU-core-hours，不扩成检索系统搜索。两臂含固定评估预计 **40–80 卡时，上限 80**；额外 CPU 约 24–40 core-hours，增量存储 ≤30 GB，计划 I/O 100–300 GB（活跃可训练表示不能冒充可永久复用的冻结 cache）。部署 p95 含检索、context 编码与冷启动，不只计最终 MLP。

**收益与证伪。** 使用第 7.1 节成本主线门槛，并单列 TSP/ATSP（D1 无新响应覆盖）的损益。若早融合只提高 TRAIN、自包含 context 的准确率，或不胜晚融合 A，停止此版；若 p95 超过点式基线 3 倍、任一 24 GB 卡装不下正确 episode 语义，也停止扩展。预算耗尽未训练完成应标 incomplete，不能把半程快照当否定。

**最强反方。** 相近平台也许不是信息进入太晚，而是上下文只重复强先验；有限压缩把必要关系再次抹掉；只有十八个任务和相似生成分布，不能像 ANP 的丰富函数族一样做元学习。R47 和大 bank ICL 的现有结果削弱它的先验胜算。若 TRAIN 内排除 base 的上下文提供清晰条件增益、且晚融合饱和而早融合能在相同预算下转成 VAL 成本收益，才提升优先级；若普通局部 ridge 同样好，应保留廉价版本，不执着于大条件网络。[DNNR 的局部几何与病态邻域分析](https://proceedings.mlr.press/v162/nader22a/nader22a.pdf) 支持保留此强反方。

### D3（优先级 3，低标签成本备选）：候选集合上的排序过程与冠军边缘概率

**对象。** 在实例 X 的完整合法池 K_t 上，学习每个剩余集合 S 的淘汰概率 eθ(j|X,S)。模型预测一整个排序分布，而非独立二分类、Borda 总分或单个成本均值。设 m(K_t)=1、其余 m(S)=0，仅对 |S|≥2 的集合由大向小递推：

\[
m(S\setminus\{j\})\mathrel{+}=m(S)e_\theta(j\mid X,S),\qquad q_k(X)=m(\{k\}).
\]

所有路径累计到 singleton，得到冠军边缘概率 q；部署按 argmax q 和固定全局候选 ID tie-break 选一方法。集合状态是概率推理内部状态，**不是**改变用户的实际候选池，也不调用 solver 观察淘汰结果。只要转移以当前集合为状态，DP 可聚合路径而无需枚举 K! 排序。当前候选规模至多十个时至多 1024 子集；仍须计算集合条件得分，不能把复杂度写成一个普通 softmax。

**历史区别与文献限制。** R71 已做全协方差混合成本差和最小值概率，R100 等也有两两/Borda 读出，所以“建模相关性”不是新方向。此版的区别是集合依赖的整个离散排序过程和精确冠军边缘化。[Choosing to Rank 的分解与单位归一化](https://arxiv.org/pdf/1809.05139) 支持这种概率对象；但论文也指出其经验改善可主要在后续名次，而首名与简单模型相近。因而“排名 likelihood 更好却 Top1 不动”是预期得到严肃对待的失败，不是继续换损失的理由。这是旧大范式报告中的未执行备选，不冒称本报告首创。

**标签与部署。** 只用冻结 TRAIN 原 FP64 成本产生排序监督；严格 winner 继续用 native ind。真实 ties 不能按 FP32 噪声任意排序：预先采用与源一致的 tie order，或在训练 likelihood 中对合法 tie 次序求和，并明确哪一个版本；不得按 TEST 决定。查询输入仅 X、合法候选 ID/描述、内部 S。候选间真实成本和排名只作 TRAIN 监督，不作集合转移输入。大量派生子集不增加独立训练 base 数。

**决定性对照。** A 在 full set 只计算一组淘汰 logits，之后各 S 仅 mask/renormalize，同样执行全路径 DP；B 在各 S 重新计算相互作用。编码器、排序监督、数据顺序、初始化、参数与可承受计算预算保持匹配，A 可配置同容量的静态交互，避免 B 只是更大。两臂都用冠军边缘概率，不能让 A 用贪心淘汰、B 用精确 DP 来偷换比较。整个方案只两臂。

**有限计划。** fresh seed2，两臂各最多 20 个完整 TRAIN epochs，默认逻辑 batch1024；长子集维度可 microbatch，但完整逻辑目标须一致。无新成本标签；排序转换 ≤8 CPU-core-hours，含训练和固定评估预计 **16–28 卡时，上限 28**，额外 CPU 约 8–16 core-hours，增量磁盘 ≤10 GB，I/O 约 30–100 GB。输入图仅编码一次；子集概率计算必须计入推理计时，不靠预存查询成本加速。

**收益、伤害与停止。** 主目标为 VAL macroTop1 相对匹配 A 至少 +0.20pp；actual regret 不增加超过 0.005pp、vsSBS 不变差，逐题 +0.05pp regret 损害门槛同前。记录全排序 NLL 与冠军 NLL 的分离、worst-task 成本及 tie-aware 指标。若只是中后名次拟合更好、冠军不改善，或者子集计算使 p95 超过点式基线 2 倍，就停止。不得加配额使每个候选必被选。

**最强反方与改判。** 已有表示可能根本分不清赢家，结构化输出只更精确地表达错误；无关的尾部排序耗掉容量；小候选池的直接分类已经足够。若成本损害而 Top1 上升，也不能替代成本主线。若 D1 不显示跨 base 信号、且 D3 在有限预算下能改善冠军而不损害成本，可把它升级为下一唯一主线；若 A 与 B 一样好，则集合依赖假说在这版不成立。

### D4（优先级 4，保留但不执行）：原生候选过程的比较式蒸馏

**对象与范围。** 教师是冻结候选在 TRAIN 上的真实运行状态序列，而非通用程序名字或合成 fragments：

\[
\tau_k(X)=(s_{k,0},a_{k,0},s_{k,1},\ldots,s_{k,L_k}),\quad
h_{k,\ell+1}=P_\theta(h_{k,\ell},X,k),\quad
\widehat z=G_\theta(\{h_{k,L}\}_{k\in K_t}).
\]

训练监督保留 native mask/pointer/resource 的类型与候选差异，学生推理自初始化、自反馈；L 由训练前锁定的输入规则限制，不能用查询真实运行长度或停止位置。候选实际轨迹只在 TRAIN 标签端出现，部署仍是 selector，不运行真实求解器前缀。首个来源 pilot 仅 CVRP、VRPL 各 32 个既有 TRAIN bases；其它任务没有新教师轨迹，full18 迁移属于待测外推。

**为什么保留、为什么不优先。** 它补的是 R113 从“合成过程”到“被选候选实际行为”的语义距离；R113 已保留预测反馈，所以不能把仅保留 feedback 重新当创新。R54/R55 的两个 ReLD 路线/计费边监督和 R61 的 encoder 迁移也不是空白：此版必须保留候选特定的有序状态过程，并在部署继续使用过程计算，才有机制区别。但这仍是旧 MP3 的更贴近原生版本，不是凭空出现第四种已验证范式。

**决定性对照。** 原生静态快照预训练对原生连续转移预训练；两者用同一批实际观测状态、相同类型解码器、同样预训练步数和 self-feedback 推理结构。静态臂只学习合法快照，不给它伪造的错误转移；转移臂额外利用真实邻接次序。两者随后以相同 fresh 基础资产和同样 full18 预算训练。比较的核心是原生次序信息，而不是额外数据量或查询执行权限。

**有限计划与成本。** 两题完整池为 10+6 候选，32 bases/题合计 **512 次原生候选执行**；已有端点成本能复用作监督，但若未保存过程，采 trace 的执行费必须重新记账。独立注释版本保留每个候选原预算和实际过程，不为统一长度修改 native 算法。若有方法无法忠实记录，标注支持不完整；不把可见子池当完整 winner 池。采集估计 8–20 卡时，硬上限 20；原生快照/转移预训练各最多 8640 updates，再各最多 20 次 full TRAIN 曝光，训练评估估计 48–96 卡时，硬上限 96，总上限 **116 卡时**。CPU 40–80 core-hours，过程增量磁盘 ≤40 GB，I/O 100–400 GB。任何一项超过上限先结束为 partial；不能截断后仍称完整原生程序。

**收益、证伪与损害。** 最终采用成本主线门槛，另报两题内状态预测有效位准确率、scalar error、合法性与错误累积。不能用 mask 多数位准确率替代可执行性；若过程学得更好但 selector 仍无净收益，接受迁移负结论。若唯一优势需要 teacher forcing、查询真实状态或真实停止时间，则直接否定其部署可行性。p95 超过点式基线 3 倍也停止。

**最强反方。** 与项目目标更相关的轨迹仍可能太长、候选差异太细，或把学习器拉向模仿 solver 而非判断 winner。[NAR for CO §5.1–5.3](https://proceedings.mlr.press/v231/georgiev24a/georgiev24a.pdf) 中伪轨迹和冻结迁移的失败，以及 [无中间监督研究 §3、§5](https://arxiv.org/html/2306.13411v2) 的计算图匹配结果，都限制“更忠实轨迹必更好”的期待。只有有限原生样本显示状态差异与可预测相对成本同时相关，并且 D1/D2 的更廉价对象不足时，才值得提高优先级；相关性仍不是因果机制证明。

## 9. 此时能说到哪一步？

可以说：已完成的 R109/R112/R113 没有提供稳定的 whole18 联合突破；若干逐题变化真实存在，但与整体指标和成本损害并存。可以说：R114 完成了限定范围的原生响应采集，显示异质性，值得一次有限学习检验。不能说：资源条件接口、算法过程或响应函数三个大范式已被全面否定；也不能说：完整标签已验证响应学习有效。

本报告的主要不确定性是单 seed、前序 TEST 的研发暴露、有限/相关的响应样本、未严格匹配的原 pilot 幅度、原生运行条件的历史覆盖边界，以及新算子预算与性能尚未测得。它们要求缩小结论和设计有停止出口的下一步，不要求重新做一个无限大的诊断工程。

推荐随证据而变：匹配随机同样好就选择便宜数据；静态端点模型同样好就停止响应计算；晚融合同样好就停止早融合；完整排名只改善尾部就停止子集过程；原生轨迹只改善教师指标就停止过程蒸馏。这样的负结果同样是完整研究产出。用户的 whole18 持续改进目标保持 ACTIVE，本次有限文献与路线交付不替它宣告完成。
